代码屏幕一直是一个紧凑的循环：你提示，代理工作，你验证。但验证之后发生的事情却是一条死胡同。轮次结束，代理在该轮中学到的任何东西都不会保留到下一轮。0.84.0 中的两个变化打破了这种模式，而且两者都默认关闭。

## 从完成的轮次中记录经验

在此版本之前，一个完成的代码轮次不会留下模型正确或错误的任何痕迹。唯一的记忆就是对话本身。这意味着每个新轮次都从相同的空白状态开始，即使代理刚刚证明它可以正确处理某种类型的任务。

代码屏幕现在在每个完成的轮次后记录一条简短的经验。该经验进入自己的存储 `code_lessons.json`，只有代码屏幕读取它——并且仅在技能卡开启时。该设置默认关闭，因为七次预注册运行发现记录的经验没有可衡量的收益。自主运行根本看不到它们。

记录的内容与去向同样重要。你从未检查过的答案被存储为未验证，而不是成功。后台工作和受污染的输出完全排除在提示之外。记录的文本有上限，因此经验存储不会无限增长。该设计假设：你没有明确验证的经验，不是你想要代理重复的经验。

铸造在此版本中也变得更加严格。每个铸造路径现在都命名其跟踪，这修复了一个错误：系统因找不到卡片来源的证据而拒绝卡片。重复检测现在需要两个共享内容词而不是一个，并且检查也适用于葡萄牙语。这一变化减少了误匹配，同时不会阻止合法匹配。

## 闭环：提交、PR 和 CI

第二个变化范围更大。在设置中开启“闭环”后，通过验证和自身差异检查的代码屏幕轮次不会就此停止。它在工作树分支上提交，推送，打开拉取请求，并在后台监视 CI 运行。如果 CI 变红，代理会读取失败并运行最多两次修复轮次。如果 CI 变绿，代理会合并拉取请求。

这在以前是不可能的。一个产生可用代码的轮次仍然需要你切换上下文、暂存更改、编写提交消息、推送、自己打开 PR，并照看检查。现在代理处理这个序列，但只有在你明确允许时才会。

保护措施是具体且不可协商的。涉及计费、破坏性迁移、行级安全或授权的拉取请求永远不会自动合并——代理会打开它，但你必须自己合并。会提交秘密的轮次什么都不提交。只有所有者的屏幕可以开启该功能或启动它。桥接、频道、访客和后台工作永远不会触发它。主分支、分离的 HEAD 和强制推送都被拒绝。该设计划定了一条硬线：自动化在可能造成不可逆损害的地方停止。

该功能默认关闭。你在所有者屏幕的设置中启用它，并且它仅适用于通过验证和差异检查的代码屏幕轮次。如果你从不开启它，你的轮次结束方式不会改变。

这两个功能共享相同的理念：记录你验证的内容，自动化你信任的内容，并且在你决定之前默认两者都不做。

开始：更新到 0.84.0，在所有者屏幕上打开设置，并决定你希望代理关闭哪些循环。完整说明见 [Chimera Agent v0.84.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.84.0)。
