## 当规则失效时

此前，包括技能存储在内的五个JSON存储允许并发进程静默覆盖彼此的数据。一次运行学到的内容可能会被下一次运行抹去。现在，这五个存储都实现了原子锁定和写入 —— 无需额外配置。同样的模式还修复了导入时崩溃的治理功能，以及一个未经验证就运行的Discord机器人。

## 技能卡片作为事故报告

现在，23张卡片存放在 `skills/` 目录下，其中13张基于本项目自身的缺陷编写。每张卡片以触发条件/操作/避免/检查/风险的格式记录故障模式 —— 这是数据，而非代码。它们按工作流阶段（`定义 · 构建 · 验证 · 审查 · 发布`）分组，并按主题标记。可以通过以下命令导入一张卡片：

```
chimera skills-import skills/verify-before-claiming
```

卡片通过附带文件支持九种语言，同时保留原始SHA-256哈希值。系统会检测过时的翻译（声称翻译已更改的文本）和不完整的翻译（缺失部分），但允许缺失翻译，并明确标记。

## 真正有效的检查点

三个代理缺陷破坏了关键组件，但未导致测试失败。根本原因在于：检查点列出了所需行为，而非允许的例外情况。当新行为出现时，检查点依然保持开放。现在，它们列出了例外情况 —— 如果某行为未明确允许绕过检查，则会被检查。

在十种语言中，修正了16项文档声明。其中五项是完全错误的：治理模式不包括 `ask`，桌面轨道没有聊天目的地，且代码库中不存在 `CHIMERA_TAVILY_API_KEY`。两项过于乐观的声明现在附带了反驳证据。

```
pip install -U chimera-agent
```
