## 你的 Agent 有了哪些变化

在此之前，让 Chimera 访问你的 Chrome 意味着接受一个二选一的决定：要么 Agent 能在浏览器里操作，要么完全不能。你没法说“在这个网站上可以，其他地方都得问我”，也没法让它只搜 Google 而不开放浏览器能做的一切。扩展本身在之前的版本里还丢掉了弹窗，导致你没法从浏览器里直接停止运行或授予站点权限。

0.72.0 版本用一套按站点信任的模型取代了那个二元开关。你列出 Chimera 可以不经询问就点击和输入的站点，在其他所有地方，每一步操作都会先给你弹出一张确认卡片。这个区别很重要，因为它贴合了人们实际的工作方式：你可能信任一个 Agent 在你内部后台的仪表盘上填表，但绝不想让它碰你的支付服务商。这个版本把这条边界明确地划了出来。即使在受信任的站点上，购买、支付、发送、删除、发布和表单提交也依然会询问。密码、卡号、验证码、支付框架、下载和上传则会被直接拒绝。遇到验证码，Agent 会停下来，把标签页交给你。

扩展在操作前还会再次检查，确认它选中的元素仍然是它即将点击的那个，并且没有任何东西遮挡在上面。这第二次检查堵上了一个缺口：页面可能在 Agent 做出决定和实际执行之间发生变化。

## Google 搜索成了一个可选项

现在，除非你主动打开，否则在你自己的 Chrome 里进行 Google 搜索的功能默认是关闭的。设置 `CHIMERA_BROWSER_GOOGLE=ask` 后，桌面端回合可以在你已配对的 Chrome 的可见标签页中搜索 Google，并且每次搜索都会先给你弹出一张卡片——即使审批设置成了允许也不例外。节奏被刻意设计得像真人操作：每 20 秒一次搜索，每回合最多五次，每天最多 30 次。结果以标题、链接和摘要的形式返回，并标记为抓取内容。

这个版本排除了什么，和它包含了什么同样重要。机器人、定时任务和 MCP 桥接器永远无法使用 Google 搜索。一旦遇到验证码或流量异常页面，它就会停下来，把标签页交给你，并且在 30 分钟内不会重试。这里面没有任何伪装。这个功能是为看着自己浏览器操作的人设计的，而不是为了无人值守的自动化。

## 配对不再泄露密钥

现在配对 Chrome 用的是屏幕上显示的六位数代码。在“设置 → 浏览器”里会显示一个一次性验证码，有效期两分钟，可尝试五次，你在扩展的弹窗里输入它。随后，密钥会存入操作系统的凭据保险库，绝不会进入 Chimera 所运行命令的环境变量里。对于在本地运行 Agent 的人来说，这是最重要的修复：单靠服务器令牌——任何本地进程都能读取——再也拿不到你的 Chrome 了。修改受信任站点列表、停止运行和取消配对，全都需要应用自身的界面操作。

发布说明直白地指出了剩余的局限性：一个已经以你 Windows 用户身份运行的恶意程序，仍然能拿走密钥。文档里是这么写的。但密钥不再躺在 Shell 环境里，不会被一条随意的命令或一个写得糟糕的 Agent 读到了。

要开始使用，请在应用中打开“设置 → 浏览器”。它会显示扩展是否已配对并连接，给你注册所需的命令，并让你列出 Chimera 可以不经询问就操作的站点。完整的发布说明在 [Chimera Agent v0.72.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.72.0)。
