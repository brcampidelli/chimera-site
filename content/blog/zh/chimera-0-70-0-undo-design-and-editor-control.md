## 终端不再是二等客户端

在此版本之前，`chimera chat` 和 `chimera assist` 的安全防护机制比桌面端要少。上下文会一直增长直到触及上限，计划在执行前不会展示，撤销一个回合意味着要信任一条更简单的恢复路径。现在，这个差距已经被抹平。

终端会话默认采用与桌面端相同的策略来压缩上下文。如果你想用旧的行为模式，可以通过 `--no-compact` 关闭。`/plan <task>` 现在会先展示计划，只有在获得批准后才会执行任务。批准计划并不等于预先批准了高风险操作。`/undo N` 会列出最近 N 个回合中涉及的文件，请求确认，并通过 Code 界面使用的同一个持久化存储进行恢复。在目标回合之后你编辑过的文件会被保留。普通的 `/undo` 依然只撤销上一个回合。

桌面端还在对话头部增加了一条回溯时间线。每个保存点都会显示时间和它涉及的文件数量。选中一个点会精确展示哪些文件将被恢复，哪些文件会因为你在之后编辑过而被跳过。恢复操作本身可以在同一条时间线上重做。没有保存副本的回合会显示为禁用状态并附带原因。预览和恢复路径都不会暴露在桌面桥接层上，因此任何配对的设备或外部客户端都无法触发恢复操作。

## 编辑器现在能反映 Git 看到的内容

以前，文件树只给你一个名字列表。现在，它会用字母标记已修改、已添加和未跟踪的文件，用点标记文件夹，使用的 Git 状态与 Changes 卡片完全一致。状态会在保存后以及智能体回合结束时刷新。Ctrl+P 可以按文件名打开文件。HTML 文件在 Code 界面使用的同一个沙箱中获得了一个预览开关，包括未保存的编辑。关闭带有未保存更改的标签页时，会询问是继续编辑、不保存关闭还是保存并关闭。

基于选区的操作改变了你请求代码帮助的方式。选中代码行并按下 Ctrl/⌘+L，可以将其作为上下文条目发送到 Code 对话中，路径与 `@` 提及相同。Ctrl/⌘+I 会添加 `propose_change`，服务端会以只读模式运行，限定在一个文件和行范围内。提案会以内联差异对比的形式返回，并带有接受和拒绝按钮。接受会通过编辑器保存。如果在回应前代码行发生了变化，提案就会消失。打开的文件如果在磁盘上发生了变化，会被保留其差异对比并保持只读状态，直到你选择保留或撤销。

Code 编写器现在支持对文件、文件夹、设计稿和最近对话的 `@` 提及。最多 8000 个字符的文件会被内联附加，经过清理，作为数据被围栏标记，并在账本中记录为一次读取。更大的文件和文件夹则通过路径交由智能体读取。绝对路径和 `..` 在回合运行前会被拒绝。指向项目外部的符号链接以及 Chimera 自身的 `.env` 文件在解析时会被拒绝。分享链接的访客不能提及设计稿或对话。

## Chimera Design 获得导出、画布和工具能力

Chimera Design 现在可以导出为 PDF、PNG 和 PPTX。PDF 是由 Playwright 的 Chromium 打印的静态页面，每个画板一页，JavaScript 处于关闭状态，非 `data:` 请求会被中止。PNG 会为每个画板生成一张图片或一个 zip 包。PPTX 会将每个元素放置在其画板对应的幻灯片帧上。当缺少 Chromium 或 python-pptx 时，导出会被拒绝并告知你需要安装什么。不会自动下载任何东西。

画布在 Code 界面的中央插槽中打开，左侧是对话，右侧是画布。它会通过操作路由自动保存，并带有可见状态。手动编辑和智能体编辑共享同一个撤销历史。一个要求设计的回合会显示“在 Chimera Design 中打开”的操作。在画布旁边，你可以根据简报提案、优化选区、审计、编辑令牌、对照令牌检查设计、按元素评论、恢复版本以及导出为 HTML。恢复和导出会先请求确认。

`design` 工具仅在一个回合要求进行视觉设计时才会被提供。一个确定性的检测器覆盖了葡萄牙语、英语和西班牙语，会折叠重音并进行全词匹配。像“设计模式”或“系统设计”这类代码语义永远不会触发它。该工具遵循姿态设置，绝不向机器人发送 HTML，将其输出标记为不可信，并且不会出现在访客回合中。`CHIMERA_TOOL_DENYLIST=design` 可以移除它。

## 现在该做什么

更新到 0.70.0 并打开一个终端会话：在执行高风险任务前运行 `/plan`，然后在任务后运行 `/undo N`。在编辑器中，选中一个代码块并按下 Ctrl/⌘+I，以差异对比的形式查看修改建议。对于设计工作，从一个要求视觉设计的回合中打开画布，并从那里导出。完整发布说明：[Chimera Agent v0.70.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.70.0).
