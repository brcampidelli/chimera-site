## 安全优先：绑定与认证机制

此前版本默认在所有网络接口暴露未认证网关端口。`docker-compose.yml`全局开放8765端口，且`.env.example`未预设令牌。这意味着单条命令部署可能意外创建开放网关，任何发现该端口的人均可访问。

v0.45.0通过三项改进解决该问题：
- `serve`命令现拒绝绑定非回环地址（除非提供认证令牌）
- Docker Compose默认仅发布在`127.0.0.1`
- 新增`--allow-insecure-bind`参数用于特殊场景（如已认证代理）

此变更为跨主机访问网关的部署环境带来破坏性变更。如需保留原功能，请设置`CHIMERA_SERVER_TOKEN`或使用应急参数。

## 真正有效的成本控制

此前版本仅通过步骤计数器限制——重试循环中的任务可能耗尽全部供应商余额。v0.45.0引入三重支出天花板：
1. 单次运行限额
2. 单任务限额（定时任务）
3. 每日累计限额（阻止定时任务触发）

未定价调用现在会中止执行而非静默继续。本地模型视为零成本而非未知状态，确保唯一不会超支的配置不受限制影响。设置限额前，请通过`chimera doctor`检查默认模型是否支持成本核算。

## 跨平台的统一治理

过去每个执行面（`serve`、定时任务、MCP、A2A及消息适配器）都构建独立工具栈。现在通过统一的`governed_profile()`为所有五个场景构建治理堆栈，并通过构建时AST检查防止退化。

关键洞察：`CHIMERA_GOVERNANCE=observe`模式可在启用前测量治理成本。该模式运行完整堆栈但仅记录会被拦截的操作，提供具体数据而非强制生产风险。默认仍为`off`状态——治理应是显式选择。

本次更新还启用了长期闲置的危险类调用审批系统，在保持攻击拦截有效性的同时消除过度拦截（误报）。

## 后续步骤

通过`pip install --upgrade chimera-agent`升级，并检查部署环境的认证与支出限制。编辑器集成需将代理设置指向`chimera acp --workspace <repo>`。完整细节见[发布说明][Chimera Agent v0.45.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.45.0)。
