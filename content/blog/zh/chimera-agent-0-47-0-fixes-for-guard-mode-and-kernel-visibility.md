## 守卫模式现能正确报告拒绝操作

守卫模式（`--guard`）存在根本性缺陷，导致被拒绝的工具调用错误显示为成功。系统原先仅检测拒绝消息中的`error:`前缀，但多数拒绝消息并不包含该标记。这意味着三个关键界面——桌面框架、步骤日志和漂移检测——都会显示危险操作已成功执行，而实际上已被拦截。模型会自信地报告诸如强制推送等从未发生的操作。现在所有界面都能正确标记拒绝操作，并明确标注为守卫决策的结果。

## 脚本与文档的规则引擎修复

规则引擎存在两个对立的问题：多行脚本总能绕过检测，因为换行转义破坏了规则模式中的单词边界识别；而引用被拦截命令的文档反而被错误地硬拦截。保护机制完全相反——真实脚本逃逸规则，文档却触发误报。由于这些解析问题，两条规则从未生效。现在插值处理能正确保持边界。

## 审计系统全面改进

修复了三个审计问题：首先，检测凭证的系统会将未脱敏的凭证存入审计日志；其次，并发写入可能破坏审计链的密码学验证；第三，安全界面因并发写入时的哈希链重置错误报告篡改行为。现在凭证在存储前会进行脱敏，写入器也能维持一致的链状态。

## 观察模式实现真实观测

`observe`模式在声称仅进行测量时仍强制执行规则。硬拦截会在审批咨询前触发，随后被排除在用于发布决策的拒绝计数外。在33次实际调用中，8次拒绝显示为零。这些拒绝记录现在能被正确统计并标识来源（它们仍是明确信号）。

## 恢复内核可见性

信任内核的判定结果此前无法传递至HTTP端点（包括运行、批处理和轮次），导致强制推送审批等关键决策不可见。当`CHIMERA_GOVERNANCE`启用时，内核现已参与所有HTTP流程。服务端提示不会出现在HTTP连接上，确保查看者确实是请求发起者。

运行`chimera upgrade`获取更新。若使用守卫模式请立即升级——前一版本的报告存在严重误导。[Chimera Agent v0.47.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.47.0)详列所有变更。

生产环境用户请检查审计日志，排查受管控的`write_file`调用是否存在凭证泄漏，并确认规则文件中的多行脚本是否需要根据修复后的边界检测进行调整。
