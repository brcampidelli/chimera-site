## 永不结束的运行

如果一个运行的子进程保持其输出管道打开，代理就会无限期挂起。读取器会无限等待管道关闭。一个继承了该管道的孙进程——比如测试运行器的 worker、一个后台服务器——会让运行、取消按钮和测试套件永远等下去。取消按钮不起作用，因为进程树还活着，而测试套件则静默冻结，而不是报告死锁。

这在 0.85.0 中得到了改变。输出读取器现在在自己的线程上运行，并在子进程退出后有五秒的宽限期。当你取消一个运行时，Chimera 会在 POSIX 系统上杀死整个进程组，在 Windows 上杀死进程树。测试套件也不再躲在冻结的墙后：如果单个测试运行超过十五分钟，套件会转储每个线程的堆栈跟踪，而不是一声不吭地锁死。你得到的是诊断信息，而不是空白的终端。

当你链接那些会生成自己子进程的工具时，这个修复最为重要——测试框架、构建脚本，或者任何会在后台 fork 一个服务器的命令。以前，这些运行是无法恢复的。现在，取消就是真的取消。

## 无需开放端口即可配对浏览器标签页

到目前为止，让浏览器标签页访问所有者的屏幕意味着要暴露桥接或聊天频道。这两条路径都带来了超出必要的攻击面。0.85.0 版本新增的配对流程将它们完全剔除。

桌面应用会显示一个八字符的验证码，有效期为五分钟，最多尝试五次。你将它输入到浏览器标签页中。该标签页会收到一个 HttpOnly、same-site 的 cookie，有效期最长十二小时，并且可以随时从桌面端吊销。只有桌面端能签发验证码——桥接和聊天频道不能。已配对的标签页无法开启桥接、无法启用完全控制，也无法切换“忽略权限”。来自它的任何状态更改请求都必须源自相同的源。

这为你提供了一个限时、可吊销、低权限的所有者屏幕访问窗口。你在需要时配对标签页，不需要时就吊销它，而桥接全程保持关闭。

## 语音消息本地落地，端点获得命名

Discord 和 Telegram 机器人现在可以听到语音消息并大声回复，并且这两件事都在你的机器上完成。语音笔记使用 faster-whisper 和固定的模型版本在本地转录。解码前会检查时长，并且每个用户都有速率限制以防止滥用。语音回复默认关闭。要开启它，你需要将 `CHIMERA_CHAT_VOICE_MODEL` 指向你自己选择的 Piper 语音 `.onnx` 文件。Chimera 不附带任何语音模型，而 `piper-tts`（GPL-3.0）位于一个单独的 `voice` 扩展中，不在 `[full]` 里。你选择加入语音功能，并且你提供语音模型。

OpenAI 兼容端点也得到了头等支持。设置 › 连接现在会列出你的端点——本地 vLLM、LM Studio 或 llama.cpp 服务器，或者托管的服务器——并允许你添加、测试和删除它们。测试仅对该端点发起一次受限的 `GET /models` 调用。只有所有者的屏幕可以更改或测试端点，密钥永远不会显示，并且端点的密钥必须是它自己的 `*_API_KEY` 变量，绝不能是其他提供商的凭证或 `CHIMERA_` 设置。这关闭了 #1133 中长期存在的请求。

## 现在该做什么

使用 `pip install chimera-agent --upgrade` 升级。在 [Chimera Agent v0.85.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.85.0) 阅读完整的发布说明。如果你使用聊天机器人并想要语音，请安装 `voice` 扩展并将 `CHIMERA_CHAT_VOICE_MODEL` 设置为你的 Piper 模型。要配对浏览器标签页，请打开桌面应用，并在所有者屏幕控件中查找配对码。
