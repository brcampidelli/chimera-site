## Agent 现在被允许做什么

在此版本之前，`chimera agent` 使用一组固定的钩子和工具权限运行。如果你想知道治理机制会对其行为做出什么决定，只能靠猜。新的 `chimera report governance` 命令改变了这一点。它按界面和可配置的天数，统计治理机制批准、拒绝、升级审查或阻止的操作。在 `observe` 模式下，它还会显示 `enforce` 模式会拒绝或发送给审批者的内容。这让你在启用更严格的策略前，可以进行一次预演。

`chimera agent` 本身现在运行在与 chat、assist 和 tui 相同的受治理程序集上。它的钩子来自其所在的项目，并且 `--deny-tools` 会覆盖延迟加载的 MCP 工具。Agent 不再运行于应用程序其余部分所使用的治理框架之外。

共享对话的安全模型也收紧了。通过分享链接访问的访客会话，以前可以访问所有者的其他对话、邮箱、日历、技能包、MCP 服务器、全局指令、钩子、浏览器登录信息以及其他对话的作业。它拥有一个 shell，可以运行任何它可能编辑过的内容，包括验证器、格式化器、钩子和 git 命令。现在它以最小权限运行。它无法读取或写入对话文件夹之外或 Chimera 自身数据之内的内容，即使通过符号链接、junction 或指令导入也不行。渲染的 PNG 和 SVG 图表拒绝远程数据 URL，快照也不再跟踪工作区之外的链接。

## 提示词的构建与衡量方式有何变化

MCP 工具描述现在可以裁剪为每个服务器一行。在 `mcp.json` 中设置 `"description_mode": "one_line"` 会向模型展示每个工具的一行描述，并通过一个受防护的 `mcp_describe` 调用来提供其余部分，该调用会遵循会话的允许和拒绝列表，包括通过账本和治理包装器。这是可选的。默认仍是完整描述，因为一项预注册的 540 次迭代配对运行测量出，裁剪导致首次调用工具选择率下降了 24.4 个百分点，置信区间为 [-31.7, -16.2]。对于那些答案位于描述尾部的任务，选择就像抛硬币一样随机。裁剪带来的好处也被量化了：对禁止操作的尝试下降了 16.7 个百分点，从 27.5% 降至 10.8%，所有这些都源于工具描述尾部的载荷。附带说明的是，良性误报并未增加。

现在提供了一个 Token 和成本基线。`scripts/token_baseline.py` 读取桌面主目录下的使用、运行和跟踪日志，并仅打印每个界面的聚合数据，覆盖价格和缓存情况，并设置了一个 30 轮对话的最低门槛，低于此门槛仅显示计数。其总数与成本界面在相同行上的数据一致。`bench/token_baseline/` 目录保存了预注册信息和首次读数。这意味着你可以跨版本跟踪提示词成本变化，而无需依赖记忆或临时测量。

工具模式快照现在按界面保存。`tests/prompt_snapshots/schema.<surface>.txt` 保存了 Code 轮次、design 轮次、CLI、cron 和 bot 发送的工具模式，由每个界面自身的函数组装而成。更改的工具描述会显示为 diff。提示词 lint 按界面对其进行总计，而 `docs/tool-schema-by-surface.md` 则用估算的 Token 数将其制成表格。这使得提示词的变更在代码审查中可见。

## 哪些问题已被修复

记忆召回以前会丢弃用俄语、中文或日语写入的事实。准入门控使用了一个仅限 ASCII 的分词器，因此召回刚刚找到的事实会因被视为不相关而被丢弃，且不显示任何消息。它现在以与召回相同的方式读取文本，代码搜索索引也照此处理。

成本数字现在在整个应用程序中保持一致。成本界面显示的缓存命中率上限为 50%。每日支出上限对自主 `solve` 运行和博客撰写器的计数方式与界面不同。现在每个主目录只运行一个 cron 守护进程，因此当应用程序和 `chimera serve --cron` 同时打开时，计划任务不会再触发两次。

回复中的链接不再能带走应用程序的凭据。桌面窗口停留在其自身的页面上，其他站点在你的浏览器中打开。它所持有的访问令牌仅授予应用程序本身，绝不会授予它被发送到的站点或其中的 dev-server 和 Design 预览。

粘贴的凭据不再留存于聊天会话文件中。聊天记录在磁盘上被屏蔽。当未设置服务器令牌时，来自其他来源的写入请求会被拒绝。附件和听写上传会经过与技能上传相同的来源检查。非 ASCII 的 bearer 头现在会得到 401 而不是 500 的响应。

存储卡以前只列出系统临时文件夹中的工作树，遗漏了项目的持久文件夹。在一台机器上，这意味着 89 个检出和 72.9 GiB 的数据未被统计。现在它会列出它们的大小、存在时间和每个仍存在的原因，在超过可配置的限制（`CHIMERA_WORKTREE_LIMIT_GB`，默认 50）时发出警告，并提供通过现有归档路径归档闲置了可配置天数（`CHIMERA_WORKTREE_IDLE_DAYS`，默认 14）的对话的选项。不会自动删除任何内容。

验证失败后的重试现在会真正升级。它会提升推理强度，然后切换到下一个单一模型，而不是重新运行同一个模型，而回执却声称使用了融合模式。融合模式不再合并任何携带工具的轮次，包括“融合此轮次”。回执中的每次尝试都会记录实际发送的模型和推理强度。

服务器分发的每个 HTML 页面现在都带有 Content-Security-Policy。FastAPI 的 `/redoc` 和 `/docs/oauth2-redirect` 在令牌防护之外提供服务，没有策略，并将 CDN 脚本加载到应用程序的源上，这些已被关闭。`/api/docs` 发送的策略精确命名了 Swagger 加载的内容。包根目录下的任何 `.htm` 或 `.xhtml` 文件都会像 `.html` 一样受到策略管控。一项新测试会请求每个页面并枚举 API 之外的每个路由，以确保下一个版本不会在没有策略的情况下发布。

通过 `pip install chimera-agent --upgrade` 升级。完整的发布说明位于 [Chimera Agent v0.90.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.90.0)。
