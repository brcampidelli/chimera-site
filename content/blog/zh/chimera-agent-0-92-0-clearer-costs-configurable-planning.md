## 成本收据与你实际调用的模型一致

之前的版本可能会让你对一次运行的真实成本感到困惑。收据依赖的上下文并不总是可用，而一个与目录条目不匹配的模型可能会回退到一个不能反映你实际调用情况的费率。这让审计支出或比较运行变得困难。

0.92.0 版本改变了 `serve` 之外运行的收据生成方式。这些运行现在使用 OpenRouter 的公开价格索引。精确的模型 slug 会获得自己的费率，而不是继承一个更宽泛或不那么精确的条目。严格调用保留准入时使用的报价，因此收据反映的是调用被准入时所接受的价格，而不是之后或不同的估算值。`gpt-oss-20b` 目录条目也已更新。

对于在服务环境之外运行代理的任何人来说，这消除了一个模糊性的来源。你可以查看收据，知道它来自公开定价，与特定的模型 slug 绑定，严格调用保留准入时的报价。这一变更不会改变模型的选择方式。它改变的是运行之后收据所报告的内容。

## 规划成为每次运行的决策

规划器之前是一个全局行为。如果你想让某个泳道、API 运行或工作流求解步骤跳过规划，没有针对该上下文的直接开关。你要么接受默认值，要么在超出任务所需的范围上改变行为。

`use_planner` 现在可以在 Kanban 泳道、API 运行和工作流求解步骤上进行配置。规划器默认保持开启。这个默认值很重要：现有设置会保持当前行为，除非你明确选择退出。新设置为那些规划会增加延迟或某个特定运行不需要的步骤的情况提供了一个更细粒度的控制点。

当一个泳道处理受限任务时，当 API 调用方知道输入已经为直接执行做好了准备时，或者当一个求解步骤应该在没有额外规划环节的情况下继续时，这非常有用。现在你可以在泳道、运行或步骤级别表达这一点，而不必改变整个系统。

## Desktop 设置真正可查找

设置搜索没有显示按角色的模型路由表。如果你不知道它在哪里，你可能要花时间在界面中点击来找到它。这个问题已修复：搜索现在可以找到路由表。

还包含两个较小的 Desktop 修复。路由和收据文案现在在巴西葡萄牙语中显示正确。新对话和仅回答的轮次也显示更清晰的状态，因此界面会告诉你正在发生什么，而不是让状态保持模糊。

## 现在该做什么

更新到 0.92.0 并检查三个变化的方面。如果你在 `serve` 之外运行代理，查看一张收据并确认它反映了你期望的模型 slug 和准入报价。如果你有不需要规划的泳道或 API 运行，在该级别将 `use_planner` 设置为 false，并在其他地方保持默认开启。如果你使用 Desktop，在设置中搜索按角色的模型路由表，并在新对话中验证状态文本。
