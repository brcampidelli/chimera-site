## 项目级模型

在此版本之前，为一个项目切换模型会同时改变所有项目中的所有对话。模型是一个全局设置，如果你想让不同项目使用不同模型，就得手动来回切换。这容易出错，也让出于一致性或成本考虑而固定项目模型的做法难以实现。

现在，每个项目都可以拥有自己的模型。Code 对话会优先使用自身固定的模型，其次使用项目模型，最后才回退到全局默认值。每轮对话的回执会显示实际使用的模型，让你一目了然。为一个项目更改模型，不再影响其他项目的对话。这意味着你可以将一个项目设为使用较便宜的模型做实验，另一个项目使用能力更强的模型跑生产，而不用担心互相干扰。

当智能体建议更换模型时，它只能给你发一张卡片，标明该建议将应用于哪个对话或项目。在你批准之前，什么都不会改变。这让你始终掌握控制权，防止智能体在对话中途悄悄切换模型。

## Claude 模型重新支持# Code 界面中可用

将 Anthropic 模型设为默认后，每次编码对话的第一步都会因工具输入 schema 错误而失败。question 工具的 schema 使用了 Anthropic API 拒绝的结构。这意味着如果你用 Claude 作为默认模型，就完全无法使用 Code 界面——每轮对话还没做任何有用的事就会报错。

现在 schema 已改为普通对象，Anthropic API 可以接受。我们增加了一个测试来检查每个工具的 schema，确保该问题不会复现。这个修复很重要，因为它保证了所有支持的模型在所有界面中都能正常工作，而不仅仅是对 schema 怪癖宽容的那部分模型。

## 现在该做什么

升级到 0.76.0 版本，如果需要，为项目设置专属模型。如果你之前因 Claude 的问题而避开 Code 界面，现在可以再试试。完整细节请参阅[发布说明][Chimera Agent v0.76.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.76.0)。
