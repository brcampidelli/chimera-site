## 费用回执与真实开销一致

在 0.92.0 之前，`serve` 之外的成本追踪依赖一份静态价目表，这份价目表会逐渐偏离服务商的实时费率。一次运行可能报出一个看似合理但实际错误的成本——有时偏差大到足以打乱预算计算。当你使用一个价目表无法识别的精确模型标识时，这种错位尤其明显：系统会回退到一个通用费率，或者干脆不显示任何有用信息。

本次发布将非 `serve` 路径的运行切换至 OpenRouter 的公开价格指数。精确的模型标识现在会解析到其专属费率，而不是被归入某个模型族的平均值。当一次调用是严格模式——即服务商和模型在准入时即被锁定——回执会保留已确认的报价，因此你看到的数字就是实际被授权的数字。`gpt-oss-20b` 的价目表条目也已更新，与当前定价保持一致。

实际效果是，你可以拿一次批量运行的回执，乘以你预期的调用量，得到一个经得起推敲的数字。再也不需要对着服务商后台手动抽查了。

## 规划器现在是一个由你控制的开关

在此之前，规划器始终处于开启状态。你无法为某个特定的看板泳道、一次 API 调用或一个工作流求解步骤关闭它。这意味着每个任务都要付出一次规划环节的延迟和 token 成本，即使任务本身很简单，或者指令已经足够明确，规划环节完全多余。

0.92.0 版本将 `use_planner` 暴露为一个配置开关。在泳道、运行或求解步骤上将其设为 `false`，agent 就会完全跳过规划阶段。默认值仍为 `true`，因此现有工作流的行为不会改变，除非你主动选择关闭。该开关在所有三个界面均可用——看板配置、API 和工作流定义——因此你可以按需选择。一个处理简单分类的泳道可以跳过规划，而旁边做多步研究的泳道则保留它。

为什么不直接让规划器变得更智能？因为猜错的成本比把开关交给你的成本更高。一个试图自行判断是否需要规划的启发式算法，有时会判断错误，而调试这种错误比翻转一个由你控制的布尔值难得多。

## 桌面端设置，真正找得到

桌面应用中的设置搜索此前会遗漏按角色分配模型的路由表。你输入“路由”或“角色”可能得不到任何结果，尽管路由表就在设置面板里。此问题已修复：路由表现在已被索引，并会在搜索结果中显示。

本次发布还附带两项本地化修复。路由表和回执文案现在能正确显示为巴西葡萄牙语——此前，部分标签会回退到英语。新对话和仅回答轮次也会显示更清晰的状态消息，让你不必再盯着一个加载图标，猜测模型是在思考还是连接已断开。

## 仍处于实验阶段的部分

几项实验在未改动默认值的情况下获得了更新。记忆提取基准测试尚无定论，因此 6,000 字符上限和全局模型保持不变。如果你想测试新路径，可以选择启用一个显式的提取模型和一个确定性的预过滤器。定时任务模型分层的实验在八个合成任务中的七个上表现出完全正确性，但合成任务并非生产任务，默认值未做更改。精简的 Design 优化和提示词比例实验也默认保持关闭。

桌面端安装包仍未签名，首次启动时可能会弹出提示。应用会验证更新包中的签名。

通过 `pip install chimera-agent --upgrade` 升级，并在你需要的地方设置 `use_planner`。完整更新日志见 [Chimera Agent v0.92.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.92.0)。
