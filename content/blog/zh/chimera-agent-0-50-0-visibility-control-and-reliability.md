## 对 Agent 操作的可见性

之前，尽管 `RunState.tasks` 字段存在，用户却无法看到 Agent 的任务列表。现在，Agent 会实时显示其任务列表，并标记任务为进行中或已完成。该列表在上下文压缩过程中保持不变，确保长时间运行不会丢失计划。这一变化解决了一个常见的痛点，即用户无法看到 Agent 在做什么，尤其是在长时间操作中。

## 超越控制台的可达性

在无人值守的情况下运行的 Agent，例如 cron 任务，无法在需要批准时有效与用户沟通。通过设置 `CHIMERA_APPROVAL_WEBHOOK`，用户现在可以在他们偏好的渠道接收批准请求。这一变化确保即使没有人在主动监控控制台，Agent 也能联系到用户。之前，如果没有可用的交付方法，这些请求会静默失败，导致意外的决策。

## 治理控制

治理功能（包括审计日志）之前无法访问。尽管安全屏幕显示了审计日志，但没有启用它的方法。现在，用户可以使用 `CHIMERA_GOVERNANCE` 参数开启治理功能。这一变化为用户提供了监控和控制其 Agent 安全设置的能力，解决了透明性和控制方面的不足。

## 改进的模型处理

之前，Agent 会为未明确编目的模型假设默认的 token 窗口大小，导致上下文溢出和运行失败。在此版本中，Agent 现在会从实时索引中获取未编目模型的正确 token 窗口大小。此外，修正了五个编目条目，以反映准确的 token 窗口和定价。这一变化防止了由于对模型能力的错误假设而导致的运行失败。

## 增强的可追溯性

现在，trace 不仅记录哪个模型回答了问题，还记录哪个后端服务了每个步骤。这对于像 OpenRouter 上的模型尤其重要，因为单个模型 slug 可能代表一组具有不同能力和成本的端点。之前，用户无法区分不同的端点，导致混淆和不准确的测量。这一变化提高了性能跟踪的透明性和准确性。

## 下一步行动

要充分利用这些改进，请更新到 Chimera Agent 0.50.0，并查看 [发布说明][Chimera Agent v0.50.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.50.0) 以获取有关配置新功能（如 `CHIMERA_APPROVAL_WEBHOOK` 和 `CHIMERA_GOVERNANCE`）的详细说明。
