## 任务现在可见

此前，Agent 维护了一个内部任务列表（`RunState.tasks`），但从未暴露或持久化。长时间运行的任务可能会在上下文压缩过程中丢失进度。现在，执行期间会显示当前任务，已完成的任务会被划掉。任务列表在压缩后依然保留，因此 Agent 不会再在执行过程中忘记计划。

## 审批请求跟随你

三种无人值守的执行场景（包括 cron 任务）可能会请求审批，但机制并不透明。如果配置了 `CHIMERA_APPROVAL_WEBHOOK`，Agent 现在会将审批问题路由到指定渠道，而不是在没有控制台时静默失败。系统还会在无法送达时明确报告 `unreachable` 状态。

## 治理与检索改进

信任内核（`CHIMERA_GOVERNANCE`）此前尽管记录了安全事件，但没有激活控制功能。现在默认禁用，并提供了一个可见的开关。在检索方面，`chimera find` 现在默认使用混合搜索（关键词 + 向量），因为测试表明在项目语料库上，混合搜索比仅关键词搜索高出 6.25 分（p = 1.7e-04）。单独的向量搜索表现不佳，因此证明了融合方法的合理性。

## 模型处理修复

Agent 此前假设未编录的模型具有 128k token 的窗口，导致 31 个模型（共 431 个索引）在实际提供 ≤64k token 时崩溃。系统现在会检查实时索引以处理未知模型。修正了五个编录条目中夸大的窗口大小，并修复了一个定价错误（偏差 2.2 倍）。

## 可追溯性与注意事项

追踪记录现在不仅记录了哪个模型回答了问题，还记录了哪个后端服务了每个步骤。这对于像 OpenRouter 这样的服务尤为重要，因为模型标识符代表的是价格差异高达 8.8 倍的池。更新日志撤回了一些性能声明，这些声明错误地比较了池化测量结果。

关键限制依然存在：安装程序未签名（尽管更新程序已签名），治理功能默认禁用，压缩摘要器默认关闭，因为实际中未被使用（137 次运行中触发次数为 0）。取消是协作式的——活动调用会在停止前完成。

详见 [Chimera Agent v0.50.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.50.0) 获取测量结果和完整更新日志。更新命令：`pip install --upgrade chimera-agent`。
