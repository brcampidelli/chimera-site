## 成本追踪的变更

在 0.92.0 之前，`serve` 外部运行的成本收据依赖一份静态的内部目录。如果模型标识未精确匹配，收据就会显示零或一个兜底费率，无法反映调用的真实成本。`gpt-oss-20b` 条目已过时，且严格准入调用丢失了准入时的报价，导致无法审计某次运行为何产生特定费用。

此版本将这些运行切换到 OpenRouter 的公开价格指数。精确的模型标识现在直接从该指数拉取自身费率。当严格调用被准入时，收据会保留准入时使用的报价，而非事后重新计算。`gpt-oss-20b` 目录条目已刷新以匹配当前定价。这些变更共同意味着，你在收据中看到的数字就是实际扣费的金额，而非来自过时查找表的近似值。

## 规划器控制移至你配置工作的地方

规划器过去始终开启，没有开关可以为特定泳道、API 运行或工作流求解步骤关闭它。如果你想让某个泳道跳过规划阶段直接执行，就必须绕过框架。当默认值变更或工作流复用泳道定义时，这种变通方案就会失效。

现在 `use_planner` 成为看板泳道、API 运行和工作流求解步骤上的一个设置项。规划器默认保持开启，因此现有配置的行为不会改变。在泳道上设置 `use_planner: false` 仅会跳过该泳道的规划阶段。在 API 运行或求解步骤上设置相同选项，则会覆盖该次执行的泳道默认值。这把决策权放在了工作定义旁边，也就是它本该在的地方，而非放在全局标志或环境变量里。

## Desktop 设置终于能被找到了

基于角色的模型路由表在此版本之前就已存在，但设置搜索并未索引它。你必须知道它在哪里，然后手动导航过去。在巴西葡萄牙语中，路由标签和收据文案渲染有误，且新对话显示的状态让人不清楚发生了什么。

设置搜索现在能找到路由表了。你可以输入角色名称直接跳转到对应分配。路由和收据文案在巴西葡萄牙语中显示正确。新对话和仅回答轮次会显示更清晰的状态，让你知道模型是在加载、思考还是等待输入。

## 未改动默认值的实验

此版本落地了三个实验，它们均未改变默认行为。记忆提取基准测试尚无定论；6000 字符上限和全局模型仍是默认值，显式提取模型和确定性预过滤器作为可选功能提供。定时模型层级实验在八个合成任务中的七个上表现出完全正确性，但合成任务并非生产任务，默认值保持不变。精简的 Design 优化和提示比例性实验默认仍处于关闭状态。

这些实验已在发布说明中记录，供希望在自己的工作负载上测试的团队参考。在未对照自有数据进行衡量之前，不要在生产环境中启用它们。

## 现在该做什么

使用 `pip install chimera-agent==0.92.0` 升级。如果你在 `serve` 外部运行成本追踪的工作负载，升级后请检查收据——数字将反映 OpenRouter 的公开指数。如果你有应跳过规划的泳道，请在泳道定义中添加 `use_planner: false`。macOS 和 Windows 上的 Desktop 用户请注意，安装程序未签名，首次启动时可能会提示；之后应用会验证更新包上的签名。完整发布说明见 [Chimera Agent v0.92.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.92.0)。
