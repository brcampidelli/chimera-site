## 对 agent 构建者来说，实际改了什么

本次发布解决了三个摩擦点：`serve` 环境之外成本追踪不透明、规划器在碍事的地方无法关闭、以及 Desktop 设置面板让路由表无法被搜索到。

这些都不是灾难性的问题。它们是那种让你再开一个终端去 grep 日志文件、或者点过四个标签页才找到所需下拉菜单的琐碎痛点。修复很小，但它们从每天要跑几十次的工作流里省掉了步骤。

## 成本收据与你实际被计费的一致

在 0.92.0 之前，在 `serve` 之外执行的运行只能猜测模型价格。框架拿不到托管环境所用的同一套费率数据，所以收据可能与 OpenRouter 实际扣费产生偏差。如果你在为客户或预算追踪每个 agent 的成本，就得手动对账。

现在这些运行会从 OpenRouter 的公开价格索引拉取数据。精确的模型 slug 使用各自的费率，而不是回退到整个系列的估算值。严格调用会保留准入时使用的报价，因此收据反映的是调用被接受时的价格，而不是事后才获取的费率。`gpt-oss-20b` 目录条目也做了更新——如果该模型是你成本基线的一部分，这一点很重要。

这个改动不影响 `serve` 内部的运行——那些本来就有准确的收据。它补齐了其他所有场景的缺口：CLI 调用、cron 任务、在工作站而非服务器上运行的流水线步骤。

## 规划器不再是强制的

`use_planner` 现在是 Kanban 泳道、API 运行和工作流 solve 步骤上的一个配置开关。规划器默认保持开启，所以除非你主动选择关闭，现有行为不会改变。

为什么这很重要：规划器会在执行前增加一轮推理。当 agent 需要把一个模糊的请求分解成具体步骤时，这很有用。但当步骤已经明确时——比如一个泳道触发已知序列，或者一个 solve 步骤用结构化输入调用单个工具——它就是额外开销。在这些情况下，规划器可能引入延迟和 token 成本，却不会改善结果。现在你可以在它不划算的地方把它关掉。

## Desktop 设置终于能被找到了

Desktop 应用的设置搜索现在索引了按角色划分的模型路由表。以前搜索 "routing" 或某个角色名什么都搜不到，尽管这个设置明明存在。你必须知道它在哪里，然后手动导航过去。这个问题修好了。

同时发布了两项本地化修复：路由和收据文案现在在巴西葡萄牙语下显示正确，新对话和仅回答的回合会显示更清晰的状态指示。这些不算功能，但它们消除了 UI 状态中的歧义。

## 仍然处于实验阶段的内容

本次发布同时进行了几项实验。记忆提取有了一个基准测试，但结果不具决定性——6000 字符上限和全局模型仍是默认值，显式提取模型和确定性预过滤作为可选功能提供。Cron 模型层级在合成任务上测试了一个更便宜的模型；八个任务中七个完全正确，但基准测试没有覆盖生产工作负载，所以默认值保持不变。设计细化和提示词比例实验仍默认关闭。除非你主动开启，这些都不会改变你的 agent 的行为。

## 现在该做什么

如果你追踪 `serve` 之外运行的成本，拿一张收据和你的 OpenRouter 账单对一下。数字应该能对上，不需要手动调整。如果你有泳道或 solve 步骤中规划器只增加延迟而没有价值，在这些配置上设置 `use_planner: false`。如果你以前通过 Desktop 搜索找不到路由表，现在试试看。

Desktop 安装包仍未签名，首次启动时可能会弹出提示。应用会验证更新包的签名。完整说明：[Chimera Agent v0.92.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.92.0)
