## 所见即所付

之前，非 `serve` 模式下运行的成本追踪基本靠猜。系统使用了一个通用回退方案，忽略了你实际调用的模型。即便你对特定模型标识做了严格准入检查，账单上显示的仍是宽泛的目录价。数字大方向没错，但细节不准，这让成本审计变得不可靠。

0.92.0 版本通过拉取 OpenRouter 的公开价格指数修复了这个问题。现在，精确的模型标识会解析到其自身费率，而不再继承系列均价。严格调用会保留准入时获取的报价，因此账单与系统已做出的决策保持一致。`gpt-oss-20b` 目录条目也已更新，以反映当前定价。如果你追踪单次运行成本或对下游消费者计费，现在看到的数字就是实际产生的数字。

## 按需控制规划器

此版本之前，规划器会在每次交互中运行。你无法为特定看板泳道、API 运行或工作流求解步骤关闭它。这给那些不需要规划的任务带来了开销——比如简单转换、确定性流水线，或者你已经知道下一步该做什么的步骤。

现在，你可以在单个泳道、API 运行和求解步骤上设置 `use_planner`。规划器默认保持开启，因此现有工作流的行为不会改变。区别在于，当规划只增加延迟而不增加价值时，你现在可以选择退出。执行单个工具调用的泳道不需要规划阶段。遵循固定序列的 API 运行不需要模型来决定下一步。控制是细粒度的：你按上下文禁用规划，而非全局。

## 真正能搜到的设置

桌面端设置曾有一个搜索框，但无法搜索按角色分配模型的路由表。那张表正是你为 `assistant`、`tool` 或 `vision` 等角色分配模型的地方。如果你忘了它在哪里，就得在面板间翻找。现在搜索索引已覆盖它。输入角色名称或模型标识，路由表就会出现在结果中。

同一次桌面端更新还修复了两个本地化遗漏。路由标签和账单文案现在能正确显示为巴西葡萄牙语。新对话指示器和仅回答轮次状态也更加清晰，消除了系统是空闲还是处理中的歧义。

## 仍处于实验阶段的内容

三项实验在未更改默认值的情况下获得了更新。内存提取基准测试尚无定论，因此 6000 字符上限和全局模型保持不变。如果你想测试更窄的内存行为，可以选择启用显式提取模型和确定性预过滤器。定时任务模型层级实验在八个合成任务中的七个上表现出完全正确性，但合成任务并非生产负载。默认值未变。精简设计优化和提示词比例实验也仍默认关闭。
