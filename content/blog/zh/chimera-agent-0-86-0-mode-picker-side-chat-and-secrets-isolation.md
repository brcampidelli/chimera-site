本次发布修复了一个结构性问题，该问题曾导致 Agent 的姿态难以信任。在 0.86.0 之前，你在设置中设定一个姿态——手动、自动或介于两者之间——然后桥接层、API 和 UI 各有各的覆盖方式。你可能会以为某次对话正以手动模式运行，结果桥接层在未告知你的情况下将其改成了自动模式。模式选择器用一个单一控件取代了这一切。

## 一个模式选择器取代三种机制

选择器位于提示词下方，通过 Ctrl/Cmd+Shift+M 打开。它列出了六种模式：手动、接受编辑、计划、自动、不再询问，以及在项目允许时忽略权限。每种模式都直接映射到现有的姿态系统。对话的模式会被保存，并从“设置”中设定的默认值开始——绝不自动变成“不再询问”，可疑时自动变为“自动”，始终默认为“手动”。“接受编辑”会在每个命令执行前显示一张卡片，除非该命令只读或沙箱已将其隔离。“计划”模式的运行范围绝不会超过“自动”模式。桥接层只能将对话切换到不扩大权限的模式，因此你锁定为“手动”的对话会一直保持手动。Ctrl/Cmd+Shift+O 打开模型选择器，Ctrl/Cmd+Shift+E 打开努力程度选择器；最大化操作移至 Ctrl/Cmd+Shift+Enter。

这很重要，因为姿态曾是你与 Agent 之间的主要安全边界，而它有两个后门。现在它有了一个所有组件都尊重的单一控件。

## Agent 的 shell 不再继承你的密钥

Agent 的子进程过去会继承诸如 `CHIMERA_OPENROUTER_KEYS`、带密码的 `DATABASE_URL` 以及云凭证等密钥池。Agent 运行的任何命令都可能将它们打印出来。桌面应用在另一个方向上存在同样的问题：它通过环境变量将服务器令牌、屏幕凭证和启动器密钥传递给后端，在 Linux 上，这些信息在 `/proc/<pid>/environ` 中对同一用户的任何进程都保持可读——Agent 的 shell 也包括在内。

两条路径现在都已关闭。Agent 的 shell 和新的终端现在获得的环境已按名称和值移除了密钥。代理设置仍然会传递。GitHub CLI 保留其所需的令牌。桌面应用现在通过 stdin 将密钥作为一行数据发送给后端，该行数据被立即读取并关闭；服务器令牌保存在内存中，而非进程环境中。如果该行数据缺失或格式错误，后端将停止启动，而不是在无令牌的情况下启动；应用也拒绝使用在无令牌情况下应答的后端。

## 侧边聊天和建议任务卡片

侧边聊天（Ctrl/Cmd+;）可以回答关于对话的快速问题，而不会将内容添加到对话中。它将对话作为数据读取，不使用任何工具作答，且不会在对话历史中写入任何内容。在此之前，问一个问题意味着要用一轮对话污染上下文，而 Agent 之后会尝试据此采取行动。“带入对话”功能只会填充到输入框；当对话读取了外部内容时，侧边聊天会引用该回答作为数据并首先询问。其成本会被记录，本地模型在每日上限内保持免费，快捷键帮助移至 Ctrl/Cmd+/。

建议任务卡片可防止 Agent 偏离主题。当它注意到任务之外的事情——死代码、过时的文档、缺失的测试、顺带发现的安全问题——它只能提议一张卡片。在任何操作运行之前，你都会看到完整的提示，并可以选择“开始”（在同一项目中开启新对话）、“在此执行”、“选项”或“忽略”。“全部开始”需要确认，且上限为五个。只有所有者的屏幕能启动卡片，由读取了外部内容的轮次提议的卡片，其对话在开始时会被标记为“受污染”且不带“忽略权限”，卡片上会显示警告。

## 现在该做什么

通过 `pip install chimera-agent --upgrade` 更新，或拉取最新的容器镜像。模式选择器、侧边聊天和终端立即可用。如果你依赖旧的姿态覆盖机制，请在升级后检查每个对话的模式——选择器会读取你的“设置”默认值，但现有对话可能在 0.86.0 之前已被桥接层移动过。密钥隔离是自动生效的，无需更改配置。完整发布说明：[Chimera Agent v0.86.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.86.0)
