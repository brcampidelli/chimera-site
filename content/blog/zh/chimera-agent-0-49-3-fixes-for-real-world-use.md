## 更清晰的 MCP 操作错误提示

在之前的版本中，MCP 数据读取是最耗费成本的问题之一。当运行因不可信内容而受到影响时，错误提示含糊不清，导致用户多次重试同一操作却无果而终。这不仅造成了不必要的开销，还引发了用户的不满。现在，错误提示针对每种场景具体说明，明确指出重试是否有用，并建议可行的替代方案，例如使用暂停等待审批的开关或完全避免不可信内容。

## 改进的 MCP 服务器测试

之前的 MCP 测试按钮仅验证服务器连通性，用户无法得知代理是否实际能使用该服务器。这导致运行因服务器未加载而失败时，浪费了大量时间和资源。现在，测试按钮会明确报告代理是否能使用服务器，针对不同原因提供不同的提示，并指导用户如何解决问题。

## 准确的验证状态

之前的运行报告基于即时快照显示 `verified: True`，但如果文件随后发生变化，这一状态可能会产生误导。现在，运行包含一个 `delivered_matches_verified` 标志，当磁盘上的文件与验证状态不匹配时，运行列表会显示一个徽章。这确保用户能察觉到差异并采取适当措施。

## 修正技能安装错误

之前的技能安装失败常被归因于 GitHub 对匿名下载的每小时限制，即使问题并非如此。现在，错误提示会正确识别拒绝请求的主机，并确保令牌能到达所有主机。此外，429 错误会根据服务器指定的等待时间重试，减少了不必要的重试。

## 精确的文件写入拒绝提示

写入文件有时会因误导性的提示而被拒绝，这些提示比较的是目录而非路径。这导致代理在重试同一操作时耗尽预算。现在，拒绝提示会准确描述路径比较，并解释工作区相对路径的 globs 模式，避免了混淆和无效尝试。

## 更新模型默认值

模型默认值已过时，部分模型落后一代，另一些则面临停用风险。默认值已更新为更近期且稳定的模型，确保更好的性能和可靠性。此外，`.env.example` 不再设置显著更昂贵或包含已停用模型的默认值。

这些改进基于实际使用场景，旨在通过解决常见痛点提升用户体验。完整详情请参阅 [Chimera Agent v0.49.3](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.49.3)。
