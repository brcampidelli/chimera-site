## 给构建智能体的人带来了什么变化

这个版本收紧了一些技术上已经存在，但实际上几乎看不见的功能区域。最明显的例子就是设置页面。以前它只是一个长长的滚动列表，“外观”藏在“通用”设置里，秘钥池、MCP、沙箱和诊断信息的行与日常偏好设置挤在一起。这样的界面难以浏览，也更难直接定位。在 0.66.0 版本中，设置页面读起来就像一篇带目录的文档。在宽窗口下，各章节都排在内容旁边，“外观”成了一个独立章节，而大多数人不会去改的选项则折叠进了“高级设置”。什么也没删，只是放到了不碍事的地方。[Chimera Agent v0.66.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.66.0)

同样的逻辑也应用到了桌面导航栏上。原本的五个图标只有悬停时才会显示名称，强迫大家去记每个图标的含义。现在，导航栏会在每个图标下面写明它的名字。代码界面的对话输入区也遵循了同样的原则。用来选择运行回合的执行者、费用方案、模型和风格的选项，以前要占用消息输入框上方的四行空间。现在它们会先显示为一行标签，点击整行才会展开。“武装熔断”和“计划”会先读成按下的轮廓，这使“发送”成了行内唯一一个填充的按钮。这个变化虽小，却消除了配置和行动之间在视觉上的竞争感。

## 应用不再“自言自语”的地方

有好几个界面会直接打印出内部标识符，而不是有意义的语义。记忆种类在每一行上都会用等宽字体显示“episodic”和“semantic”。不管应用是什么语言，日程安排都用英文来描述。个人信息部分会显示“chat”和“extracted”这类来源 ID，外加存储的“tainted”标记，不论语言环境是什么，统统显示英文。已学习技能的行也会同样把“tainted”和“retire?”标识出来，而且第二个还用上了表示失败的红色。工作区 › Git 的确认框直接调用浏览器原生的确认弹窗，这种弹窗既无法列出文件名，看起来也和应用风格格格不入。

上述每一种情况，都是界面暴露了数据模型，而不是呈现了决策。这个版本会翻译记忆种类，用应用所使用的语言来描述日程安排，并让个人信息用一句完整的话来说明一个事实的来源。未验证的计数和“无操作系统沙箱”的提示从红色改成了琥珀色，因为它们是需要复核的状态，而非错误。Git 的丢弃询问现在会出现在按钮下方，用红色显示，把“取消”放在首位，且每个文件复选框都带有文件名。在葡萄牙语中，“连接”和“使用情况”页面也不再使用术语：之前的标签被替换成了 Ferramentas externas (MCP)、Ferramentas 和 APIs (OpenAPI)。

## 现在该做什么

更新到 0.66.0 并打开设置。新的“外观”板块可以调整强调色、表面色调和高对比度选项，并且每种组合都经过了对比度检查。接着打开工作区 › 运行记录，在一长串历史记录中使用搜索和结果筛选功能；一次运行的早期尝试会折叠在最终决策的那个回合下面。如果你维护着指向应用内部的链接，请注意“知识库”和“自动化”标签现在有了独立地址，这样它们就能在刷新后保留状态，并支持浏览器的后退键。完整列表请查阅版本发布说明。[Chimera Agent v0.66.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.66.0)
