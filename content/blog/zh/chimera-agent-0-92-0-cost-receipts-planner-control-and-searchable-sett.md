## 所见即所付

在 `serve` 之外启动运行时的费用追踪，之前完全脱离实际。框架使用的是一个过时的内部目录，根本不反映服务商的真实收费。如果你通过脚本或测试套件运行智能体，收据上显示的数字与账单毫无关系。这对任何在部署前需要本地迭代的人来说，预算管理形同虚设。

0.92.0 版本将这些运行接入了 OpenRouter 的公开价格索引。当你传入精确的模型标识时，框架会查询该特定费率，而不是退回到模糊匹配。严格调用现在会保留准入时捕获的报价，因此收据金额与服务商在接受请求时承诺的费用一致。`gpt-oss-20b` 目录条目也已更新，反映当前定价。结果就是单一事实来源：收据上的数字，就是你将在服务商账单上看到的数字。

这一点很重要，因为智能体构建者经常用廉价模型测试，再在生产环境中切换到更大的模型。没有精确的按模型费率，不同运行之间的成本比较毫无意义。现在你可以并排比较两次规划器运行，并确信收据上的差异反映了真实的支出差异。

## 规划器不再总是开启

在此版本之前，规划器在每个回合、每种上下文中都会运行。无法针对特定看板泳道、API 调用或工作流求解步骤禁用它。这给那些不需要规划的任务——简单检索、确定性转换，或下一步动作已知的步骤——强加了规划开销。唯一的变通方法是分叉工作流定义，并祈祷一切正常。

现在 `use_planner` 是一个配置标志。可以在泳道上设置它，在 API 运行时传入，或附加到求解步骤上。规划器默认保持开启，因此现有工作流的行为不会改变。但当你知道某个步骤不需要规划时，就关掉它，省去一次往返。这能降低混合了规划密集型和无规划阶段的管道的延迟和成本。

## 找得到的桌面设置

桌面应用的设置搜索之前忽略了按角色分配模型的路由表。你可以搜索 "router" 或 "routing"，却得不到任何结果，尽管该表是应用中最复杂的配置界面。唯一到达它的方式是滚动设置面板直到认出来。这让新用户的入门更加困难，也拖慢了想快速调整角色分配的老用户。

搜索索引现在包含了路由表。输入角色名称或模型，搜索就会返回匹配条目。同一次更新修复了两个本地化问题：路由标签和收据文案现在能正确显示为巴西葡萄牙语，之前截断的字符串和缺失的翻译让界面令人困惑。新对话和仅回答回合也显示了更清晰的状态消息，让你知道智能体是在等待输入还是在处理中。

## 仍处于实验阶段的内容

几项实验在未更改默认值的情况下收到了更新。记忆提取基准测试尚无定论，因此 6000 字符上限和全局模型保持不变。如果你想测试新路径，可以选择显式提取模型和确定性预过滤器。定时任务模型层级实验在八个合成任务中的七个上表现出完全正确性，但合成任务不是生产负载，默认值未变。精简设计优化和提示比例实验也默认保持关闭。

这些实验在链接的笔记中有文档说明。如果你正在运行记忆密集型智能体或定时工作流，这些可选标志值得在预发布环境中测试。

## 获取此版本

使用 `pip install chimera-agent --upgrade` 升级，并通过 `chimera --version` 检查版本。桌面安装包未签名，首次启动时可能会提示；应用会验证更新包签名。完整说明见 [Chimera Agent v0.92.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.92.0)。
