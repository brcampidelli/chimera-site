## 对 Agent 构建者而言，实际改了什么

本次发布中有三项改动会改变你日常运行 agent 的方式。其余均为默认关闭的实验性功能，它们属于实验室，不该进你的流水线。

**费用收据不再靠猜。** 在 0.92.0 之前，`serve` 之外的运行没有可靠的定价来源。收据显示的是本地目录中缓存的任何内容，对于较新的模型，这些数据可能已过时或缺失。如果你使用的精确模型标识不在目录中，费用行要么错误，要么干脆没有。对于任何固定使用特定提供商端点的人来说，这都破坏了预算控制。

现在，`serve` 之外的运行会拉取 OpenRouter 的公开价格索引。精确的模型标识会获取其自身费率，而非继承一个模糊匹配的结果。严格准入调用会保留准入时使用的报价，因此收据与实际预留的内容一致。`gpt-oss-20b` 目录条目也在同一轮次中得到了更新。如果你追踪每次运行的成本，现在的数字是可复现的。

**规划器变成了一个开关。** 规划器以前始终开启。你无法为单个看板泳道、单次 API 调用或工作流中的单个求解步骤关闭它。这意味着每个轻量级任务都要承受规划带来的延迟和 token 开销，即使指令很简单，或者模型无法从任务分解中获益。

通过 `use_planner`，你可以在关键位置进行设置：在泳道定义中、在 API 运行负载中，或在工作流求解步骤中。默认值仍为开启，因此现有行为不会改变。但如果你有一个只做格式化输出的泳道，就可以跳过规划器，省下一次往返。同一个标志位在三个层面都有效，因此心智模型就是一个布尔值，而不是三套不同的配置。

**桌面端设置变得可查找了。** 按角色分配模型的路由表之前藏得很深。你必须知道它在哪个设置标签页下，然后滚动找到它。现在设置搜索已将其索引，输入“路由”或某个角色名称就能找到。当你在不同项目间切换，且这些项目对同一角色使用不同模型时，这一点很重要。

同时发布了两项本地化修复：路由和收据的文案现在能正确显示为巴西葡萄牙语，新对话和纯回答轮次会显示更清晰的状态。状态改动虽小，但消除了轮次是在等待工具调用还是等待模型响应时的歧义。

## 实验性功能意味着什么（以及不意味着什么）

四项实验性功能已落地，均为可选加入，且默认关闭。除非你明确启用，否则它们不会改变生产行为。

记忆提取进行了一轮基准测试，结果尚无定论。6000 字符上限和全局模型仍是默认值。你可以选择启用显式提取模型和确定性预过滤器，但目前尚无证据表明这两者能可衡量地改善召回率。如果你想收集自己的数据，可以启用它们。

定时任务模型层级在合成任务上进行了测试。在八项任务中，更便宜的层级在七项上完全正确。这并不能说明它在你的生产定时任务上的表现，因为合成任务不等于你的任务。默认值未变。如果你运行大量定时任务，可以尝试更便宜的层级，并根据你自己的成功标准进行验证。

设计细化和提示比例性仍默认关闭。它们是内部实验，尚无面向用户的界面。说明中提到它们是为了保持透明，而不是让你去动它们。

## 现在该做什么

如果你追踪成本，拉取最新镜像并在 `serve` 之外运行一个任务。对照 OpenRouter 公布的费率检查收据。如果你固定使用精确的模型标识，请验证费率行是否与你的提供商一致。

如果你有轻量级看板泳道，为某个泳道添加 `use_planner: false` 并比较延迟。该标志位在运行配置模式中有文档说明。

如果你使用桌面端，打开设置并搜索一个角色名称。确认路由表出现了。
