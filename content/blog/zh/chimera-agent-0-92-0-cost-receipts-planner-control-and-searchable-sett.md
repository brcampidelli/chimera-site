## 费用收据的变更

此前，在 `serve` 外部执行的任务依赖一份静态或不完整的价目表。当模型标识未能精确匹配时，收据要么显示错误的费率，要么直接省略费用行。这使得审计微调变体或新发布模型的支出变得非常困难。

0.92.0 版本将这些运行切换至 OpenRouter 的公开价格指数。精确的模型标识现在会直接从指数中拉取自身费率。严格调用还会保留准入时接受的报价，因此收据反映的是智能体实际承诺的价格，而非事后的估算。`gpt-oss-20b` 目录条目已刷新，以匹配当前定价。

对于任何在 `serve` 路径之外追踪单次运行成本的人来说，收据现在无需手动修正即可做到准确。只要模型在公开指数中列出，智能体就能正确计价。如果标识未知，收据会明确说明，而不是默认静悄悄地归零。

## 规划器不再总是开启

在此版本之前，规划器会在每个泳道、每次 API 调用以及每个工作流求解步骤上运行。对于那些增加规划延迟却无法改善结果的简单任务，没有办法禁用它。希望在简单泳道上更快执行的团队，不得不绕过框架来解决问题。

`use_planner` 现在是一个暴露在看板泳道、API 运行和工作流求解步骤上的配置标志。规划器默认保持开启，因此除非你主动选择关闭，否则现有行为不会改变。在泳道上将该标志设为 `false` 会完全跳过规划阶段，直接进入执行。

这对处理确定性、单步操作的泳道影响最大。一个获取已知端点或按固定模式转换负载的泳道，并不会从规划过程中受益。移除规划能减少延迟并降低 Token 消耗，同时不影响正确性。该标志是按泳道设置的，因此你可以在同一个项目中，为模糊任务保留规划器，而为机械性任务关闭它。

## 桌面端设置支持搜索

桌面应用中的设置搜索此前不会索引按角色分配的模型路由表。要查找哪个模型被分配给特定角色，需要滚动浏览整个列表。随着团队添加更多角色和回退模型，这种摩擦感会越来越强。

搜索功能现已覆盖路由表。在设置搜索栏中输入角色名称或模型标识，会直接返回匹配的路由条目。同一次更新还修复了巴西葡萄牙语的路由和收据复制问题，此前截断的标签使路由表难以阅读。新的对话和纯回答轮次也显示了更清晰的状态指示器，让你知道智能体是在等待模型响应，还是在处理工具调用。

## 保持选择加入的实验性功能

几项实验性功能已落地，但未更改默认设置。使用显式模型和确定性预过滤的内存提取功能已可用，但处于关闭状态。基准测试尚无定论，因此 6,000 字符上限和全局模型保持不变。一个成本更低的 cron 模型层在合成任务上进行了测试，八项中正确完成了七项，但未测量生产工作负载。设计细化和提示词比例实验也默认保持关闭。

这些功能都隐藏在特性标志之后，供希望在自己环境中测试的团队使用。没有任何东西是自动变更的。

## 现在该做什么

使用 `pip install chimera-agent==0.92.0` 进行升级。如果你在 `serve` 外部运行智能体，请检查你的下一份收据，确认定价与 OpenRouter 的公开价格指数匹配。对于不需要规划的泳道，在泳道配置中添加 `use_planner: false`。桌面端用户可以打开设置并搜索角色名称，以验证路由表是否已被索引。
