## 推理强度下沉到角色级别

在此版本之前，在 agent 文件上设置推理强度会应用一个全局值，这很容易引起误解。现在，agent 文件的 `effort` 字段仅控制该子 agent 自身的调用。代码角色和 fusion cast 的强度来自一个新的环境变量 `CHIMERA_ROLE_EFFORTS`，它按角色而非按 agent 设置强度。仓库中的 agent 文件无法提高所有者选择的强度，因此拉取的 agent 不会在无意中消耗超出预期的推理 token。

这很重要，因为强度是一个成本杠杆。对摘要角色使用高强度会浪费钱；对规划角色使用低强度则会产生脆弱的计划。以前那种一刀切的设置迫使我们做出取舍，但这并不符合角色实际消耗推理资源的方式。现在，你在适用的地方设置强度，系统会拒绝任何试图提高强度的覆盖操作。

## 提示缓存在失效时会发出警告

提示缓存只有在真正命中时才能省钱。以前，对话可能在没有信号的情况下滑入低缓存命中率区域。你只会在事后通过电子表格注意到成本。现在，当在报告缓存的路由回合中，从缓存读取的提示 token 占比低于 80% 时，回合收据和状态栏会警告一次，并指出主要原因。当缓存恢复并再次降级时，该警告会重新激活。从不报告缓存的路由不会产生警告，因此你不会被那些从未期望过缓存的事情打扰。

Worth 还增加了一个每次解决运行的成本指标。它显示所有运行的总成本除以通过的运行数，以及每个验证器确认运行的成本，还有已知价格的运行占比。当任何运行缺少价格时，Worth 会显示一个破折号，而不是误导性的数字。表格保持按名称排序，而不是排名，因为 Worth 是一个诊断工具，而不是排行榜。

## 访客只能看到答案，看不到内部运作

以前，共享对话会泄露所有者的工具参数、编辑差异、审批预览、浏览器截图、验证器输出、指令来源、成本收据和主机路径。实时观看、回放或检查模型上下文的访客可以重建出远超答案本身的信息。这个漏洞现已关闭。访客现在只能通过一个白名单接收答案、工具名称和状态，该白名单会丢弃任何无法识别的帧类型。所有者的内部运作保留在所有者的屏幕上。

## 新数据文件夹的治理模式默认设为观察

全新安装现在以 `observe` 模式启动治理，记录在 `governance_default.json` 中。在 `observe` 模式下，内核的固定硬阻止会拒绝诸如 `rm -rf /`、`mkfs` 或 curl 管道到 shell 的命令。`enforce` 模式下会发送审查的内容现在仅被记录，不会询问。现有的数据文件夹保持 `off` 状态，并在日志中收到通知，在设置中收到一个可关闭的提示。显式设置 `CHIMERA_GOVERNANCE` 仍然优先，空值视为未设置。这意味着新安装从第一次运行起就被锁定，无需设置者阅读单独的安全页面。

## 计划任务拥有自己的模型、强度和步骤预算

现在，cron 任务可以通过 `cron add/edit --model --effort --max-steps` 或 Schedule 界面指定自己的模型、强度和步骤预算。空值会像以前一样从 `serve` 继承。无效值在保存时会被拒绝；手动编辑的 `jobs.json` 如果包含错误值，加载时会发出警告，而不是静默丢弃该任务。任务的最后交付答案（最多 2 KB）会关闭其上下文，这样它就不会在多次调用中重复自己。被目标地址拒绝的交付会计入失败制动器，并且永远不会被视为已交付。命名这些字段的 Webhook 任务会被拒绝，因为 webhook 携带自己的配置。

## 现在该做什么

使用 `pip install chimera-agent --upgrade` 升级并重启你的服务器。如果你在 agent 文件中设置了推理强度，请将这些值移到 `CHIMERA_ROLE_EFFORTS` 中，并仅为子 agent 调用设置 agent 文件的 `effort`。检查你的共享对话：访客将不再看到内部帧，你无需做任何更改即可获得此保护。新安装默认获得 `observe` 治理模式；现有文件夹保持不变，除非你显式设置 `CHIMERA_GOVERNANCE`。完整说明见 [Chimera Agent v0.91.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.91.0)。
