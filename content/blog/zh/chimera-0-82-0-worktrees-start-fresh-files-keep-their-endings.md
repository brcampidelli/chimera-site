## 工作树从远端拉取，不再基于过期的本地检出

以前，新建工作树会基于本地当前检出的任何内容。如果本地克隆落后了好几天，Agent 就会从旧代码开始工作，且对此一无所知。第一轮对话可能浪费时间去解决早已修复的问题，或者引入稍后才会暴露的冲突。

现在，工作树请求会先拉取远端的默认分支，并从该提交创建新的工作树。输出信息会标明它基于哪个提交开始。当无法连接远端时，Agent 会回退到本地 HEAD 并发出警告。拉取过程绝不会弹出凭证提示，因此操作不会因为等待不可能到达的输入而挂起。

这一点很重要，因为基于过期代码工作的 Agent，产出的内容在隔离状态下看似正确，但一放到仓库当前状态下就会失败。这一改动消除了 Agent 所见与团队其他人所见之间的隐性偏差。

## Chimera 写入的文件保留原有换行符

Agent 的文件写入曾经过一个文本模式，在 Windows 上会将所有换行符转换为 CRLF。在 Windows 上创建的文件会与仓库的 LF 规范冲突，导致本地通过的翻译哈希在 CI 上失败。这种不匹配很难排查，因为在会标准化换行符的 diff 工具里，文件看起来完全一样。

现在，写入操作是逐字节精确的。新文件使用 LF。已有的 CRLF 文件保持 CRLF。翻译哈希忽略换行符，因此在一个平台上计算的哈希与在另一个平台上计算的哈希一致。这个修复消除了一个特定于平台的故障，该故障曾破坏 CI 流水线，并迫使开发者去调试他们无法直接看到的 Agent 输出。

## 在命令被禁用的环境下，Agent 会先询问再动手

在一个禁用了命令的文件夹里发起编程请求，过去会让工具空跑一个小时，最后才报告它无法检查任何东西。Agent 编辑了代码，什么都没测试，然后交付了一个未经验证的答案。所有者事后才发现问题。

现在，Agent 会在运行任何工具之前停下来，询问所有者是允许执行命令、在无命令模式下继续，还是取消。只有所有者的屏幕可以授予权限。如果一轮对话发生时屏幕前没人，它绝不会等待——而是直接以无命令模式继续。这个选择会按对话记住，未经验证的答案会在顶部明确说明这一事实。这一改动避免了浪费工作，并在 Agent 行动之前就让约束条件清晰可见。

## 其他影响日常使用的修复

缺失验证工具不再将一轮对话标记为失败。当一轮对话后的检查因程序未安装而无法运行时——比如在一个没有 `node_modules` 的全新工作树里运行 `vitest`——该轮对话会显示为未验证，并附带原因和修复方法。`.chimera/verify.toml` 中的 `setup` 命令可以安装缺失的组件。如果检查的测试确实运行了且失败了，则仍会显示为失败。这种区分让你能看清是 Agent 的输出破坏了测试，还是测试运行器根本不存在。

记忆提取失败不再静默。当 Code 轮次背后的记忆提取无法启动时，应用会记录一条包含错误类型的警告——绝不包含对话内容或密钥——并且该轮对话仍会正常回答。以前，这种失败不会留下任何痕迹，你无法知道为什么 Agent 看起来忘记了上下文。

已安装的应用无论在哪个文件夹打开，都会保留其密钥。后端过去会读取启动文件夹的 `.env`，并为后台服务记录该文件夹。从其他终端打开的应用启动时没有提供者密钥，导致每一轮对话都失败。开始菜单快捷方式掩盖了这个问题。现在，打包构建的应用始终在其安装文件夹中运行后端。

数字微调在你输入完成时生效，而不是每按一次键就触发。在一个范围从 28 到 56 的微调器里输入 `34`，过去会先发送 `3`，被拒绝，然后弹回。现在，该字段仅在离开字段或按下回车键时一次性应用，并钳制到范围内，按 Esc 键则丢弃草稿。

README 不再称 Chimera 为自我进化。七次预先注册的学习运行没有发现可衡量的收益，因此标题、包描述、CLI 帮助、应用以及翻译后的 README 现在都只陈述证据支持的事实：一个受管控的、会发布自己零结果发现的 Agent。翻译后的 README 也不再承诺一个学习循环并未运行的 A/B 测试。

桥接页面现在对对话列表进行分页和过滤。通过 Claude 桥接列出对话过去会一次性返回全部 1,465 条。现在它接受 `limit`、`cursor`、`state`、`project` 和 `q` 参数，桥接层默认每页 50 条，而屏幕上无参数的列表保持不变。
