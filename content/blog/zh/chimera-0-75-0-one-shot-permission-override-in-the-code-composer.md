## 对你有什么变化

到目前为止，任何触及沙箱外部的工具调用都会弹出一个审批卡片。你得一个一个点。这就是既定的契约：智能体停下，你来决定，它再继续。即使你正在迭代一个脚本，智能体需要连续运行同一个安全命令十二次，这个契约依然有效。这种摩擦不是 bug——是设计使然。但它让快速迭代变得比实际需要的更慢。

0.75.0 版本在 Code Composer 中增加了一个开关，名为“忽略权限”。打开后，智能体会自动批准那些通常会弹出审批卡片的工具调用。它会记录下替你做出的每一个决定。这个开关仅对单次会话生效，应用重启后不会保留。并且，它不会触及任何向外发送本地数据的操作：推送、发布、支付、以你名义发送的消息、访问密钥，以及任何将数据传输出本机的操作仍然会暂停并询问。边界是明确的。智能体在边界内可以更快行动；但未经你允许，它无法越界。

这不是一个全局设置，也不是配置文件里的开关。它是屏幕上的一个按钮，只有你能按下。这种设计让权限跳过紧贴着工作本身。你看着对话，你知道智能体在做什么，然后你决定，在这次会话中，那些重复的审批都是噪音。应用重启后，噪音会回来。你需要再次刻意地选择加入。

## 为什么超时行为变了

Code 界面之前对你的回复设定了五分钟的截止时间。如果你没在这个窗口内响应审批卡片，智能体就会拒绝调用，对话就会停滞。当时的假设是，未响应的卡片意味着无人值守的会话。但这个假设在一种常见的工作流中失效了：你让智能体做件事，然后切到另一个窗口查文档或验证一个想法，六分钟后回来发现对话已经死了。超时机制惩罚了专注。

现在，Code 界面会无限期等待你的回复。智能体保持暂停，直到你回来。五分钟限制仍然在它有意义的地方保留——比如没人盯着的自动化任务。那些地方依然有护栏。但当你人在电脑前，即使暂时离开，对话也不会再自行过期了。

## 这个开关不做什么

“忽略权限”开关不是一个 sudo 标志。它不会提升权限，不会授予智能体任何它原本无法请求的访问权限。它仅仅是移除了让你手动批准每个请求的要求。智能体仍然会记录每一次自动批准的调用。事后你可以审查发生了什么。如果你需要审计一次会话，记录就在那里。

仍然需要明确批准的类别是那些将数据移出本机或消耗资源的操作：推送到远程仓库、发布操作、支付行为、带有你身份标识的消息，以及任何读取或向外传输密钥或本地数据的操作。这个开关无条件地尊重这些类别。不存在第二个开关来跳过这个跳过机制。

## 现在该做什么

更新到 0.75.0。打开一个你预期会有重复工具调用的 Code Composer 会话。找到屏幕上的“忽略权限”开关。当审批卡片变成噪音时，打开它。当你需要护栏回来时，关掉它。重启应用即可重置。在[发布说明][Chimera Agent v0.75.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.75.0)中阅读完整的变更列表。
