## 当MCP读取被阻止的写入时

此前通过MCP读取数据会污染运行状态，且不解释写入失败原因。错误提示将三种不同场景混为一谈：用户拒绝、所有者配置、以及HTTP请求完全无法获得人工批准的情况。用户对所有情况都看到相同的拒绝信息，导致在根本不可能成功的重试上浪费时间和预算。现在每种情况都会获得具体说明——特别在HTTP上下文中，消息会明确指出批准不可行，并建议启用暂停等待批准功能或避免加载不可信内容。

## 真正有效的测试

此前MCP测试按钮仅验证服务器连接性，却隐藏了代理是否实际能使用这些工具的关键信息（当禁用启动时加载MCP服务器功能时，服务器可能通过测试但其工具仍不可用）。现在测试会同时报告连接状态和实际可用性，并提供不同消息说明如何解决各类潜在问题。

## 验证与交付的差异

运行验证先前只显示`verified: True`而不指示当前文件是否匹配已验证版本。已验证的运行后续可能包含完全不同的内容（实际观察到20/20测试失败的案例），且无视觉提示。现在运行会追踪`delivered_matches_verified`状态，并在磁盘内容与验证状态不符时显示明确标识。

## 模型默认配置更新

默认模型阵容已落后于当前市场：
- 基础模型从`deepseek-chat-v3.1`（0.25/0.95）更换为`deepseek-v4-flash-0731`（0.065/0.18）
- 顶级模型用`z-ai/glm-5.3`替代了`deepseek-r1`
- 融合评审与专家席模型更新至当前世代

这些变更基于实测的价格、上下文窗口尺寸和第三方基准改进——而非未经验证的质量宣传。更新还移除了预览模型在用户未明确选择时的默认位置。

## 其他修复
- 技能安装错误现在能正确识别拒绝请求的主机
- 绝对路径写入权限会清晰对比工作区相对路径的glob模式
- `.env.example`不再推荐已弃用模型或错误价格

通过`pip install --upgrade chimera-agent`更新或查看[Chimera Agent v0.49.3](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.49.3)获取完整详情。
