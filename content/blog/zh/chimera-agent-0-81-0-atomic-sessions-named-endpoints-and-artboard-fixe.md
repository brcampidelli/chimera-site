## 并行轮次不再损坏会话

重新打开一个 Code 会话时，过去会原地重写其会话文件。写入操作基于一次读取，而这次读取发生在长达十秒的等待之前。在这个窗口期内，另一个读取者或一次崩溃会看到半个文件。在此期间保存的轮次会丢失。在大量并行轮次下，这损坏了多个会话及其备份。

本次修复使会话写入原子化、刷入磁盘，并在进程间加锁。重新打开步骤现在只合并它实际获取到的字段。你不再因为读取和延迟写入之间的竞态而丢失轮次。如果你对同一个会话运行多个 agent，或在某个轮次进行中重启，文件将保持完整。

## HTML 画板获得自有资源和检查器

在此版本之前，HTML 画板从一个 token 级别的列表中拉取字体，该列表写成一个带引号的名称。屏幕在画布上和导出时会回退到衬线字体。检查器始终显示第一个画板，因此第二个 HTML 屏幕无法进行微调或选择其元素。

现在，每个设计都保留自己的图片和字体存储。你可以从助手添加 PNG、JPEG、WebP 或 GIF 图片，以及 WOFF2、WOFF 或 TTF 字体。助手知道存在哪些资源。屏幕和导出会使用它们。SVG 和伪装文件会被拒绝。在画布上，资源以内联数据形式到达，因此沙盒化的屏幕仍然无法访问网络。

点击画板或其标签会将其设为活动画板。检查器会随之切换。第二个 HTML 屏幕拥有自己的元素选择和样式微调。设计系统的字体在画布上和导出时都能正确渲染。

## 命名端点取代全局基础 URL

以前，将模型路由到 OpenAI 兼容的提供商意味着要全局设置 `CHIMERA_API_BASE`。每个模型都经过这个单一基础地址。如果不自行代理，你无法在一个配置中混合使用多个提供商。

`CHIMERA_ENDPOINTS` 按名称列出端点。每个条目声明一个基础 URL 和保存其密钥的变量。写成 `endpoint/<name>/<model>` 的模型会使用其自身的基础地址和密钥访问该端点，与 OpenRouter 并列。隐私卡、回执和使用面板会显示端点名称及其主机。`/api/endpoints` 会列出并测试它们。

这是多提供商路由工作的一部分。你为不同的提供商保留独立的密钥，agent 将每个模型路由到正确的基础地址，无需前置代理。

## 在消息中命名的连接器仅在该轮次连接

在 MCP 自动加载关闭的情况下，如果一个 Code 轮次的消息命名了一个已配置、已启用的连接器，则仅连接该连接器。该轮次会说明这一点，并为后续命名该连接器的轮次保留连接。来自工具、页面或文件的文本永远不会开启连接器。Bot 保留自己的列表。

这可以防止检索到的文档中的一次提及就静默启用一个你无意使用的连接器。你通过在消息中键入的内容来控制连接。

## 减少摩擦的小修复

当一条消息命名了 Chimera Design，同时要求代码路径、pytest 命令或诸如 fix、implement、test 等词语时，不再打开画布。系统不再将工程工作解读为设计请求。

URL 连接器的详情卡不再声称测试会启动命令，或 npx 可能下载包。环回地址上的服务器不再带有“访问网络”的标签。卡片描述的内容现在与连接器的实际行为一致。
