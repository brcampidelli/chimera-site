## エージェントが現在許可されていること

このリリース以前は、`chimera agent` は固定されたフックとツール権限のセットで実行されていました。そのアクションに対してガバナンスがどのような判断を下したかを知りたい場合、推測するしかありませんでした。新しい `chimera report governance` コマンドはそれを変えます。サーフェスごと、かつ設定可能な日数にわたって、ガバナンスが許可、拒否、レビュー依頼、保留した件数をカウントします。`observe` モードでは、`enforce` が拒否するか承認者に送信したであろう内容も表示します。これにより、より厳格なポリシーを有効にする前にドライランを実行できます。

`chimera agent` 自体は、chat、assist、tui と同じガバナンスアセンブリ上で動作するようになりました。そのフックは作業対象のプロジェクトから取得され、`--deny-tools` は遅延 MCP ツールにまで到達します。エージェントは、アプリケーションの他の部分が使用するガバナンスフレームワークの外で動作することはなくなりました。

セキュリティモデルは、共有会話に対しても強化されました。共有リンクを通じてアクセスされたゲストターンは、以前はオーナーの他の会話、メールボックス、カレンダー、スキルバンドル、MCP サーバー、グローバル指示、フック、ブラウザサインイン、他の会話のジョブに到達可能でした。シェルを持ち、検証ツール、フォーマッタ、フック、git コマンドなど、編集可能なものは何でも実行できました。現在は最小権限で実行されます。シンボリックリンク、ジャンクション、指示のインポートを通じても、会話のフォルダ外や Chimera 自身のデータ内を読み書きすることはできません。レンダリングされた PNG および SVG チャートはリモートデータ URL を拒否し、スナップショットはワークスペース外へのリンクを辿らなくなりました。

## プロンプトの構築と計測方法の変更点

MCP ツールの説明をサーバーごとに1行に切り詰められるようになりました。`mcp.json` で `"description_mode": "one_line"` を設定すると、モデルには各ツール説明の1行が表示され、残りはフェンスされた `mcp_describe` 呼び出しを通じて提供されます。これはセッションの許可リストと拒否リストを尊重し、台帳とガバナンスラッパーを通じて行われます。これはオプトインです。デフォルトは完全な説明のままです。事前登録された540反復のペア実行において、切り詰めによる初回呼び出しツール選択率が -24.4 パーセンテージポイント（信頼区間 [-31.7, -16.2]）と計測されたためです。回答が説明の末尾にあるタスクでは、選択はコイントスになります。切り詰めによって得られるものも計測されています。禁止アクションの試行は 27.5% から 10.8% へと 16.7 パーセンテージポイント減少し、その全てがツール説明の末尾のペイロードによるものでした。注意点はありますが、良性の誤検知が劣ることはありませんでした。

トークンとコストのベースラインが利用可能になりました。`scripts/token_baseline.py` はデスクトップホーム配下の使用状況、実行、トレースログを読み取り、サーフェスごとの集計のみを表示します。価格とキャッシュのカバレッジ、および30ターン未満ではカウントのみを表示する下限付きです。その合計は、同じ行に対するコスト画面と一致します。`bench/token_baseline/` ディレクトリには事前登録と最初の読み取りが保持されます。これにより、記憶や場当たり的な測定に頼ることなく、バージョン間でのプロンプトコストの変化を追跡できます。

ツールスキーマのスナップショットがサーフェスごとに保持されるようになりました。`tests/prompt_snapshots/schema.<surface>.txt` は、Code ターン、デザインターン、CLI、cron、bot が送信するツールスキーマを保持し、各サーフェス自身の関数によって組み立てられます。変更されたツール説明は diff として表示されます。プロンプトリントはサーフェスごとにそれを集計し、`docs/tool-schema-by-surface.md` は推定トークン数とともにそれを表形式にまとめます。これにより、コードレビューでプロンプトの変更が可視化されます。

## 壊れていたが修正されたもの

メモリ呼び出しは、以前はロシア語、中国語、日本語で書かれた事実を取りこぼしていました。入場ゲートが ASCII のみの単語分割器を使用していたため、リコールが見つけたばかりの事実が無関係としてメッセージなしで破棄されていました。現在はリコールと同じ方法でテキストを読み取り、コード検索インデックスもそれに倣います。

コスト数値がアプリケーション全体で一致するようになりました。コスト画面はキャッシュヒット率を最大50%で表示していました。デイリー支出上限は、自律的な `solve` 実行とブログライターを画面と同じ方法でカウントしていませんでした。現在はホームごとに1つの cron デーモンのみが実行されるため、アプリと `chimera serve --cron` の両方が開いているときにスケジュールされたジョブが2回実行されることはなくなりました。

返信内のリンクがアプリの認証情報を持ち出すことはできなくなりました。デスクトップウィンドウは自身のページに留まり、他のサイトはブラウザで開きます。保持するアクセストークンはアプリ自体にのみ付与され、送信先のサイトや内部の dev-server およびデザインプレビューに付与されることは決してありません。

貼り付けられた認証情報がチャットセッションファイルに残らなくなりました。チャットトランスクリプトはディスク上でマスクされます。サーバートークンが設定されていない場合、別オリジンからの書き込みは拒否されます。添付ファイルとディクテーションのアップロードは、スキルアップロードと同じオリジンチェックを受けます。非 ASCII の Bearer ヘッダーは、500 ではなく 401 を返すようになりました。

ストレージカードは、以前はシステム一時フォルダ内のワークツリーのみをリストし、プロジェクトの永続フォルダを見逃していました。あるマシンでは、89のチェックアウトと 72.9 GiB が未計上でした。現在はサイズ、経過時間、各々がまだ存在する理由とともにそれらをリストし、設定可能な制限（`CHIMERA_WORKTREE_LIMIT_GB`、デフォルト 50）を超えると警告し、設定可能な日数（`CHIMERA_WORKTREE_IDLE_DAYS`、デフォルト 14）アイドル状態の会話を既存のアーカイブルートを通じてアーカイブすることを提案します。何も自動的に削除されることはありません。

検証失敗後のリトライが実際にエスカレーションするようになりました。推論努力を引き上げ、その後、レシートがフュージョンを主張している間に同じモデルを再実行するのではなく、次の単一モデルに移行します。フュージョンは、「このターンをフューズ」を含む、ツールを運ぶターンには参加しなくなりました。レシートの各試行は、実際に送信されたモデルと努力を記録します。

サーバーが配信するすべての HTML ページに Content-Security-Policy が付与されるようになりました。FastAPI の `/redoc` と `/docs/oauth2-redirect` は、トークンガード外でポリシーなしで提供され、CDN スクリプトをアプリのオリジンにロードしていましたが、オフになりました。`/api/docs` は、Swagger がロードするものを正確に指定したポリシーを送信します。バンドルルートにある孤立した `.htm` や `.xhtml` は `.html` と同様にポリシー適用されます。新しいテストは、すべてのページを要求し、API 外のすべてのルートを列挙するため、次回はポリシーなしで出荷されることはありません。

`pip install chimera-agent --upgrade` でアップグレードしてください。完全なリリースノートは [Chimera Agent v0.90.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.90.0) にあります。
