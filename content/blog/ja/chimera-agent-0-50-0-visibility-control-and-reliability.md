## エージェント操作の可視化

以前は、`RunState.tasks`フィールドが存在していたにもかかわらず、ユーザーにはエージェントのタスクリストが見えませんでした。今回のアップデートで、エージェントはタスクリストをリアルタイムで表示し、進行中や完了した項目をマークするようになりました。このリストはコンテキストの圧縮後も保持されるため、長時間の実行中でも計画を失うことがありません。これにより、特に長時間の操作中にエージェントが何をしているのかわからないというユーザーの不満が解消されます。

## コンソールを超えたリーチャビリティ

cronジョブなどの無人で実行されるエージェントは、承認が必要な場合にユーザーと効果的にコミュニケーションを取ることができませんでした。`CHIMERA_APPROVAL_WEBHOOK`を設定することで、ユーザーは承認リクエストを好みのチャネルで受け取れるようになりました。これにより、コンソールを誰も監視していない場合でも、エージェントがユーザーにリーチできるようになります。以前は、配信方法が利用できない場合、これらのリクエストはサイレントに失敗し、予期しない決定がなされることがありました。

## ガバナンス制御

監査ログを含むガバナンス機能は、以前はアクセスできませんでした。セキュリティ画面に監査ログが表示されていたものの、有効にする方法がありませんでした。現在では、`CHIMERA_GOVERNANCE`パラメータを使用してガバナンスを有効にできます。この変更により、ユーザーはエージェントのセキュリティ設定を監視および制御できるようになり、透明性と制御性のギャップが解消されます。

## モデル処理の改善

以前のエージェントは、明示的にカタログ化されていないモデルに対してデフォルトのトークンウィンドウサイズを想定していたため、コンテキストオーバーフローや実行失敗が発生していました。今回のリリースでは、エージェントはカタログ化されていないモデルの正しいトークンウィンドウサイズをライブインデックスから取得するようになりました。さらに、5つのカタログエントリが正確なトークンウィンドウと価格を反映するように修正されました。これにより、モデルの能力に関する誤った想定による実行失敗が防止されます。

## トレーサビリティの強化

トレースは、どのモデルが応答したかだけでなく、どのバックエンドが各ステップを処理したかも記録するようになりました。これは特にOpenRouterのようなモデルにとって重要です。OpenRouterでは、単一のモデルスラグが、異なる能力とコストを持つエンドポイントのプールを表すことがあります。以前は、ユーザーは異なるエンドポイントを区別できず、混乱や不正確な測定が生じていました。この変更により、パフォーマンス追跡の透明性と正確性が向上します。

## 次にやること

これらの改善を活用するには、Chimera Agent 0.50.0にアップデートし、`CHIMERA_APPROVAL_WEBHOOK`や`CHIMERA_GOVERNANCE`などの新機能の設定に関する詳細な手順を[リリースノート][Chimera Agent v0.50.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.50.0)で確認してください。
