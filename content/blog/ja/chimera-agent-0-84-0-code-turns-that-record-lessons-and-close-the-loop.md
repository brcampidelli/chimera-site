コード画面はこれまで常にタイトなループでした。プロンプトを出し、エージェントが作業し、あなたが検証する。しかし検証後の流れは行き止まりでした。ターンが終了し、そのターンでエージェントが学んだことは次のターンに引き継がれませんでした。0.84.0の2つの変更がこのパターンを打ち破りますが、どちらもスイッチはオフで出荷されます。

## 完了したターンから記録される教訓

このリリース以前は、完了したコードターンはモデルが何を正しく行い、何を間違えたかの痕跡を残しませんでした。唯一の記憶は会話そのものでした。つまり、エージェントが特定の種類のタスクを正しく処理できることを示した直後でも、新しいターンは同じ空白状態から始まっていました。

コード画面は各ターンの完了後、短い教訓を記録するようになりました。教訓は専用のストア `code_lessons.json` に保存され、コード画面のみがそれを読み取ります。そしてスキルカードが有効な場合のみです。この設定はデフォルトでオフのままです。7つの事前登録された実行では、記録された教訓による測定可能な利益が見られなかったためです。自律実行ではそれらを一切見ません。

何が記録されるかは、どこに保存されるかと同じくらい重要です。確認していない回答は成功ではなく未検証として保存されます。バックグラウンド作業や汚染された出力はプロンプトから完全に除外されます。記録されるテキストには上限があり、教訓ストアが無制限に成長することはありません。この設計は、明示的に検証していない教訓はエージェントに繰り返してほしくない教訓であるという前提に基づいています。

ミンティングもこのリリースで厳格になります。すべてのミンティングパスがトレースに名前を付けるようになり、カードがどこから来たかの証拠が見つからないために拒否されるバグが修正されました。再発検出は1つではなく2つの共有コンテンツワードを必要とするようになり、チェックはポルトガル語でも機能します。この変更により、正当な一致を妨げずに誤検出を減らします。

## ループを閉じる：コミット、PR、CI

2つ目の変更はより広範です。設定で「ループを閉じる」を有効にすると、検証と自身の差分チェックを通過したコード画面のターンはそこで止まりません。ワークツリーブランチにコミットし、プッシュし、プルリクエストを開き、バックグラウンドでCIの実行を監視します。CIが赤で戻ってきた場合、エージェントは失敗を読み取り、最大2回の修正ターンを実行します。CIが緑で戻ってきた場合、エージェントはプルリクエストをマージします。

これは以前は不可能でした。動作するコードを生成したターンでも、コンテキストを切り替え、変更をステージし、コミットメッセージを書き、プッシュし、自分でPRを開き、チェックを見守る必要がありました。今ではエージェントがその一連の流れを処理しますが、明示的に許可した場合のみです。

保護策は具体的で交渉の余地がありません。請求、破壊的なマイグレーション、行レベルセキュリティ、または権限付与に触れるプルリクエストは自動的にマージされません。エージェントはそれを開きますが、マージは自分で行う必要があります。シークレットをコミットするターンは何もコミットしません。この機能を有効にしたり開始したりできるのはオーナーの画面のみです。ブリッジ、チャンネル、ゲスト、バックグラウンド作業がそれをトリガーすることはありません。メインブランチ、デタッチドHEAD、フォースプッシュはすべて拒否されます。この設計は明確な線を引きます：不可逆的な損害が可能になる場所で自動化は停止します。

この機能はデフォルトでオフです。オーナーの画面の設定で有効にし、検証と差分チェックを通過したコード画面のターンにのみ適用されます。有効にしなければ、ターンの終了方法に何も変わりません。

両方の機能は同じ哲学を共有しています：検証したものを記録し、信頼したものを自動化し、あなたが別段の決定をするまでどちらも行わないことをデフォルトとします。

開始するには：0.84.0にアップデートし、オーナーの画面で設定を開き、エージェントにどのループを閉じさせたいかを決めてください。完全なノートは[Chimera Agent v0.84.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.84.0)にあります。
