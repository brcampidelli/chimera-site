## MCPが書き込みをブロックした場合

以前、MCP経由でデータを読み取ると、書き込みが失敗した理由を説明せずに実行が汚染されていました。エラーメッセージは、ユーザーによる拒否、所有者の設定、そして人間がHTTPリクエストを承認できない場合という3つの異なるシナリオを一括りにしていました。ユーザーはこれらすべてに対して同じ拒否メッセージを見ることになり、再試行に時間と予算を無駄にしていました。今回の更新では、各ケースに特化した説明が追加され、特にHTTPコンテキストでは、承認が不可能であることを明確に示し、pause-for-approvalを有効にするか、信頼できないコンテンツを避けることを提案します。

## 実際にテストを行うテスト

以前のMCPテストボタンは、サーバーの接続性を確認する一方で、エージェントが実際にそれらのツールを使用できるかどうかを黙って隠していました。サーバーがテストに合格しても、エージェントがツールを使用できない場合（MCPサーバーの起動時に読み込みが無効になっている場合）がありました。現在、テストは接続性と実際の可用性の両方を報告し、各潜在的な問題を解決する方法を明確に説明します。

## 検証と配信の区別

以前の実行検証では、`verified: True`と表示されても、現在のファイルが検証されたものと一致しているかどうかは示されませんでした。検証済みの実行が後で完全に異なる内容を含む場合（観測されたケースでは20/20のテスト失敗）があり、視覚的な表示はありませんでした。現在、実行は`delivered_matches_verified`を追跡し、ディスクの内容が検証された状態から乖離している場合に明確なバッジを表示します。

## モデルのデフォルト設定が更新

デフォルトのモデルラインナップは現在の提供から遅れていました：
- ベースモデルが`deepseek-chat-v3.1`（0.25/0.95）から`deepseek-v4-flash-0731`（0.065/0.18）に変更
- トップティアモデルが`deepseek-r1`から`z-ai/glm-5.3`に置き換え
- 融合判定とパネルシートが現行世代のモデルに更新

これらの変更は、価格、コンテキストウィンドウサイズ、およびサードパーティのベンチマークにおける測定された改善を反映しています。また、ユーザーが明示的に選択していないプレビューモデルをデフォルトの位置から削除しました。

## その他の修正
- スキルインストールエラーが、どのホストがリクエストを拒否したかを正しく識別
- 絶対パスの書き込み権限が、ワークスペース相対のglobパターンとの明確な比較を表示
- `.env.example`が非推奨のモデルや誤った価格設定を提案しなくなりました

`pip install --upgrade chimera-agent`で更新するか、詳細は[Chimera Agent v0.49.3](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.49.3)をご覧ください。
