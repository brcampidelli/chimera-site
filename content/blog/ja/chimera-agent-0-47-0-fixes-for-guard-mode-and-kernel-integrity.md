## Guard Modeが拒否を正しく報告するよう修正

ツール呼び出しを拒否したゲートが、以前は`error:`で始まらない観測文字列を返していたため、システムが成功として記録していました。これにより、デスクトップフレーム、ステップログ、ドリフト検知の3箇所に影響が発生。危険なアクションがすべてブロックされた実行でも、構造化データ上は成功として表示され、実際には発生していないforce pushなどの完了アクションがモデルから報告されるケースがありました。カーネルが正しく拒否をマークするよう修正され、拒否テキストでどのガードが決定したか識別可能になりました。

## 複数行スクリプト向けルールマッチングの修正

以前のルールエンジンはスクリプトテキストを`repr`でインターポレートしていたため、改行が2文字にエスケープされていました。これによりルールパターンの単語境界が崩れ、2つの問題が発生:

1. `\n`が次の単語と融合するため、単純な1行スクリプトが保護を回避可能
2. 危険なコマンドを引用したMarkdown文書が誤ってブロックされる

この問題により2つのルールが全く発動しませんでした。テキストはエスケープなしでルールに渡されるよう修正され、実際のスクリプト動作と一致します。

## 監査システムが秘密情報を保存しないよう修正

管理対象の`write_file`操作が、`.env`ファイルや秘密鍵などの機密データを含む完全なファイル内容を`audit.jsonl`に保存していました。他のガードが操作をブロック済みの場合でも発生していました。監査システムは既存の編集機能（以前はステップトレースのみで使用）を使って機密コンテンツを編集し、ドキュメント型引数をサイズのみのメタデータとして記録するようになりました。

## HTTPエンドポイントにカーネル可視性を追加

信頼カーネルの判定が、run/batch/turnエンドポイントのHTTPレスポンスに含まれていませんでした。これによりforce push承認などの重要な決定がクライアントから不可視になっていました。`CHIMERA_GOVERNANCE`が`observe`または`enforce`の場合、カーネルがHTTPサーフェスに正しくインストールされるよう修正。HTTPデプロイではサーバーのターミナルでプロンプトが表示されない点に注意（そのコンソールの人物がリクエストを発行していないため）。

## その他の修正

- 監査チェーンが並行書き込みによる改ざんを誤報告しないよう修正
- `observe`モードが計測対象の拒否を正しくカウントするよう修正
- スタックしたワーカーがバッチ全体を無期限に保持しないよう修正
- コンテナリソース制限を設定可能に
- ターミナル使用にコンテキスト予算制御を追加

## 既知の制限事項

チームは現在の3つのギャップを発見待ちではなく明示的に文書化:

1. `observe`レポートがHTTPインターフェースにまだ表示されない
2. APIに`enforce`モード用の承認パスが不足
3. 4つのHTTPエンドポイントにまだカーネル判定が含まれない

`pip install --upgrade chimera-agent`で更新するか、詳細なリリースノートは[Chimera Agent v0.47.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.47.0)を参照。
