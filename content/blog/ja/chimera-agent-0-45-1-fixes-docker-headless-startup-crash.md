## Docker デプロイメントの起動時クラッシュが解消

Chimera Agent 0.45.0 で、ゲートウェイサービスを実行するヘッドレス Docker コンテナが起動直後にクラッシュするリグレッションが発生していました。この問題は、cron パスが `chimera.api.usage` のインポートを開始し、Docker イメージが意図的に `desktop` エクストラを含めていないにも関わらず、FastAPI 依存関係の積極的なインポートをトリガーしたために発生しました。

この問題はテストで検出されませんでした。なぜなら、開発環境には通常 FastAPI がインストールされているためです。2,945件の既存テストはすべて、依存関係がたまたま存在する環境で実行されたため合格していました。この障害は、最小限の `.[full]` インストールを使用する本番デプロイメントでのみ明らかになりました。

## レイジーインポートで隠れた依存関係を防止

修正は、単に不足している依存関係を追加するのではなく、根本原因に対処しています。以前は、`chimera/api` 内の5つのCLI到達可能なリーフモジュールが、`__init__.py` での積極的な再エクスポートを通じてWebスタック全体を静かに取り込んでいました。v0.45.1ではこれらのインポートをレイジーにし、Web向けコンポーネントによって実際に必要とされる場合にのみロードされるようにしました。

これにより、コアCLI/ゲートウェイがWeb依存関係を必要とすべきでないという文書化された分離が維持されつつ、正当なWeb使用ケースでFastAPIが不足している場合に `chimera app` が明確に失敗するようになります。

## 新しいテストでリグレッションを防止

専用のテストが追加され、`fastapi` を意図的にインポート不可にしたサブプロセスでこの動作を検証します。テストはまずこの環境設定が機能することを確認してから他のアサーションに進むため、環境汚染によりテストが黙って通過してしまうケースを捕捉できます。

修正はクリーンな `.[full]` インストールでエンドツーエンド検証されました。ヘッドレスDockerデプロイメントで `serve --cron` が期待通り実行できるようになりました。

この問題の影響を受ける既存のデプロイメントは、v0.45.1にアップグレードしてください。[リリースノート][Chimera Agent v0.45.1](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.45.1)にv0.45.0からの変更の詳細が記載されています。
