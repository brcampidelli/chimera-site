## LiteLLM Gateが任意のプロバイダーキーを受け入れるようになりました

以前のChimeraは、LiteLLMの5つのプロバイダーしか認識せず、GroqやMistralなどの有効なキーを「プロバイダーキーが設定されていません」という誤解を招くエラーで拒否していました。現在、ゲートは任意の`<PROVIDER>_API_KEY`を受け入れ、以下の2つのセーフガードを備えています：

1. モデルプロバイダー以外（ElevenLabsやStability AIなど）が誤ってモデルソースとして識別されるのを防ぐための拒否リスト
2. `doctor`がLiteLLMの列挙型に対してプロバイダー名を検証し、それ以外の場合は静かに失敗するタイポを捕捉

この変更は、より深い問題に対処しています。Pydanticの`extra="ignore"`設定により、`.env`に配置されたキーが無視されていました。`chimera init`が`.env`ファイルを作成し、ドキュメントがユーザーにその場所を指示しているため、これが永続的な設定失敗を引き起こしていました。

## 以前は隠されていた機能が利用可能に

コード内に存在していたがユーザーインターフェースがなかった3つの重要な機能が利用可能になりました：

1. **エージェントレジストリ**: ボードのレーンボックスは、表示されないレジストリIDを推測する自由入力フィールドでした。現在、Automationの3番目のタブからアクセス可能で、既存のエージェントを表示しつつ、存在しないIDに対して作業をファイルすることも可能です（バックログで待機）。
2. **埋め込みモデル選択**: 以前は隠されていましたが、セマンティックメモリスイッチの直下に表示されるようになりました。失敗するとレキシカル検索に静かに劣化するため、設定の可視化が重要です。
3. **キープール**: これらはクールダウン付きでラウンドロビン方式で回転していましたが、UIがありませんでした。現在、インターフェースは秘密の値を公開せずに操作（追加/削除）で管理します。

## コア機能に対する重要な修正

アプリ内で壊れていた2つの機能が修正されました：

- **ファイルアップロードとメッセージディクテーション**: `authHeaders()`が`application/json` Content-Typeを強制したため、適切なマルチパートフォーム境界が設定されず、422エラーが発生していました。API層全体をモックしていたため、テストでは見逃されていました。
- **セッション永続化**: ランダムなポート割り当てにより`localStorage`のオリジンが変更され、アプリが起動時にテーマ、ワークスペース、言語設定を失っていました。現在、ポートを記憶して再利用します。

初回実行ウィザードもモデル選択をより適切に処理し、プロバイダーに互換性のあるモデルを表示（自動適用はしない）して、即座の401エラーを防ぎます。

`pip install --upgrade chimera-agent`で更新するか、詳細は[Chimera Agent v0.43.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.43.0)を参照してください。
