## セキュリティ最優先: バインドと認証

以前のバージョンのChimera Agentは、デフォルトで全てのネットワークインターフェースに認証不要のゲートウェイを公開していました。`docker-compose.yml`はポート8765をグローバルに公開し、`.env.example`にはトークンが設定されていませんでした。つまり、1コマンドのデプロイで、ポートを発見した誰もがアクセス可能なオープンなエージェントゲートウェイが意図せず作成される可能性があったのです。

v0.45.0ではこれを3つの方法で変更します:
- `serve`コマンドは、認証トークンなしで非ループバックアドレスにバインドすることを拒否するようになりました
- Docker Composeはデフォルトで`127.0.0.1`のみに公開します
- 正当なケース（認証済みプロキシなど）のための明示的な`--allow-insecure-bind`フラグが存在します

これは、別のマシンからゲートウェイにアクセスしているデプロイメントにとって破壊的変更です。必要に応じて`CHIMERA_SERVER_TOKEN`を設定するか、エスケープハッチを使用してください。

## 実際に機能する支出制御

このリリース以前は、ステップカウンターが唯一の制限でした - リトライループ内のジョブがプロバイダーの残高を全て使い切る可能性がありました。v0.45.0では3つの独立した支出上限を導入します:
1. 実行ごとの制限
2. ジョブごとの制限（スケジュールされたタスク用）
3. cronジョブの発火を防ぐ日次集計制限

価格設定されていない呼び出しは、暗黙的に継続するのではなく実行を停止するようになりました。ローカルモデルは未知ではなくゼロコストとして扱われ、過剰支出できない唯一の構成がブロックされないようになります。制限を設定する前に、`chimera doctor`を実行してデフォルトモデルに価格設定が可能か確認してください。

## 全実行表面での統一ガバナンス

以前は、各実行表面（`serve`、cron、MCP、A2A、メッセージングアダプター）が独自のツールレジストリを構築していました。現在は単一の`governed_profile()`が5つ全てのスタックを構築し、ビルド時のASTチェックで後退を防ぎます。

重要な洞察: `CHIMERA_GOVERNANCE=observe`モードは、有効化前に強制のコストを測定するために存在します。これは完全なスタックを実行しながら、ブロックされるものを記録するだけで、本番リスクを強制せず具体的なデータを提供します。デフォルトは`off`のままです - ガバナンスは明示的なオプトインであるべきです。

このリリースでは、危険クラス呼び出しのため長らく休眠状態だった承認システムも配線され、攻撃ブロックの効果を損なうことなく過剰ブロック（偽陽性）を排除します。

## 次のステップ

`pip install --upgrade chimera-agent`でアップグレードし、デプロイメントの認証と支出制限を確認してください。エディター統合の場合は、エディターのエージェント設定を`chimera acp --workspace <repo>`に向けてください。詳細は[リリースノート][Chimera Agent v0.45.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.45.0)をご覧ください。
