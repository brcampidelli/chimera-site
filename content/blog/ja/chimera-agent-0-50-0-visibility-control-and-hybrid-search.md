## タスクの可視化

これまでエージェントは内部タスクリスト（`RunState.tasks`）を保持していましたが、公開も永続化もされていませんでした。長時間の実行では、コンテキストの圧縮中に進行状況を把握できなくなる可能性がありました。現在では、実行中のアクティブなタスクが表示され、完了したタスクには取り消し線が引かれます。このリストは圧縮後も保持されるため、エージェントが実行中に計画を忘れることはありません。

## 承認リクエストの追跡

3つの無人実行環境（cronジョブを含む）が承認を要求できるようになっていましたが、そのメカニズムは不透明でした。`CHIMERA_APPROVAL_WEBHOOK`を設定すると、エージェントは承認質問を指定されたチャネルにルーティングし、コンソールが利用できない場合のサイレントな失敗を回避します。また、配信が不可能な場合には明示的に`unreachable`状態を報告します。

## ガバナンスと検索の改善

信頼カーネル（`CHIMERA_GOVERNANCE`）は、セキュリティイベントをログに記録していたにもかかわらず、有効化制御がありませんでした。現在ではデフォルトで無効化され、可視化されたトグルスイッチが用意されています。検索機能では、プロジェクトのコーパスでキーワードのみの検索を6.25ポイント（p = 1.7e-04）上回る性能が確認されたため、`chimera find`はデフォルトでハイブリッド検索（キーワード＋ベクトル）を使用するようになりました。ベクトル検索単体では性能が劣るため、融合アプローチが正当化されています。

## モデル処理の修正

エージェントはカタログに登録されていないモデルが128kトークンのウィンドウを持つと想定していましたが、実際には64k以下しか処理できない31モデル（インデックスされた431モデル中）が存在し、クラッシュを引き起こしていました。システムは現在、未知のモデルに対してライブインデックスをチェックします。5つのカタログエントリで過大評価されていたウィンドウサイズが修正され、1つの価格誤差（2.2倍の誤差）が修正されました。

## トレーサビリティと注意点

トレースは現在、どのモデルが回答したかだけでなく、各ステップを処理したバックエンドも記録します。これは、モデルスラッグが8.8倍の価格変動があるプールを表すOpenRouterのようなサービスで重要です。変更履歴では、プールされた測定値を誤って比較していた一部の性能主張が撤回されています。

主な制限事項は残っています：インストーラーは未署名（ただしアップデーターは署名済み）、ガバナンスはデフォルトで無効、圧縮サマライザーは実際には使用されていないためデフォルトでオフ（137回の測定実行で0回のトリガー）。キャンセルは協調的で、アクティブな呼び出しは停止前に完了します。

測定値と完全な変更履歴は[Chimera Agent v0.50.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.50.0)を参照してください。更新するには：`pip install --upgrade chimera-agent`
