## Улучшенная изоляция песочницы

Настройка песочницы по умолчанию была обновлена для повышения безопасности. Ранее песочница `local` не была изолирована, полагаясь на ядра управления и запросы подтверждения для защиты вашей машины. Этот подход имел уязвимости, особенно когда пользователи пропускали запросы или когда инструкции внедрялись. Теперь по умолчанию используется `auto`, который применяет **Seatbelt** на macOS с профилем `(deny default)` и **bubblewrap** на Linux с строгими параметрами изоляции. Это обеспечивает изоляцию сети и ограничивает запись в рабочий и временный каталоги, значительно снижая потенциальные риски.

## Особенности для Windows и ядра Linux

Для Windows в обновлении явно указано, что механизм песочницы не предоставляется. Существующие ограниченные токены и сетевые фильтры не приближены, так как отсутствие границы менее опасно, чем ложное убеждение в её наличии. Аналогично, ядра Linux, которые отказываются от непривилегированных пространств имён пользователя, будут сообщать, что песочница *недоступна*, обеспечивая прозрачность в отношении ограничений безопасности.

## Экономически эффективная модель по умолчанию

Модель по умолчанию была изменена с GPT-5.5 на DeepSeek V3.1. Это изменение решает проблему высокой стоимости предыдущей модели по умолчанию, которая была самой дорогой в каталоге. DeepSeek V3.1 предлагает более экономичный вариант по цене $0.25/$0.95 за 1 млн токенов по сравнению с $5.00/$30.00 для GPT-5.5. Переменная окружения `CHIMERA_DEFAULT_MODEL` по-прежнему имеет приоритет, а выбор модели позволяет изменять её для каждого диалога.

## Улучшения на основе аудита

Обширный аудит выявил множество рекомендаций, при этом 56% работы было сосредоточено на настройке, а не на функциях продукта. Этот выпуск решает многие из этих проблем, обеспечивая корректное выполнение кода и точное ведение логов. Заметные исправления включают корректную обработку отказанных инструментов, удаление неудачных cron-задач и защиту строк, содержащих учетные данные. Каждое исправление было тщательно протестировано путем отмены изменений и проверки, что тесты обнаруживают дефекты.

## Новые функции и улучшения

Новые функции включают хранение учетных данных в системном хранилище ключей (`chimera secrets`), механизм утверждения решений (`chimera approve`) и ход кодирования, который сохраняется при разрыве соединения. Кроме того, команды, доказанно только для чтения, больше не требуют подтверждения, а серверы MCP могут быть открыты, а не переданы. Три новых этапа в CI дополнительно повышают надежность системы.
