## Когда правила не доходят

Пять JSON-хранилищ, включая хранилище навыков, ранее позволяли параллельным процессам тихо перезаписывать данные друг друга. Запуск, который что-то узнал, мог быть стёрт из памяти следующим запуском. Все пять теперь блокируются и записывают атомарно — без необходимости настройки. Тот же подход исправил функции управления, которые падали при импорте, и Discord-бота, который работал без проверок.

## Карточки навыков как отчёты об инцидентах

Двадцать три карточки теперь находятся в `skills/`, тринадцать из которых написаны на основе дефектов самого проекта. Каждая документирует режим отказа в формате Триггер/Действие/Избегать/Проверить/Риск — данные, а не код. Они сгруппированы по фазам рабочего процесса (`define · build · verify · review · ship`) и помечены по темам. Импортируйте одну с помощью:

```
chimera skills-import skills/verify-before-claiming
```

Карточки поддерживают девять языков через дополнительные файлы, которые сохраняют оригинальный SHA-256 хэш. Система обнаруживает устаревшие переводы (утверждающие, что переводят изменённый текст) и неполные (отсутствующие разделы), но позволяет отсутствие переводов с чёткой маркировкой.

## Гейты, которые действительно блокируют

Три дефекта агента подрывали ключевые компоненты, не вызывая сбоев в тестах. Основная причина: проверки перечисляли требуемые поведения вместо разрешённых исключений. Когда появлялись новые поведения, гейты оставались открытыми. Теперь они перечисляют исключения — если что-то явно не разрешено обходить проверки, оно проверяется.

Шестнадцать утверждений в документации были исправлены в десяти языках. Пять были полностью ложными: режимы управления не включают `ask`, настольный рельс не имеет чата назначения, и `CHIMERA_TAVILY_API_KEY` не существует в кодовой базе. Два оптимистичных утверждения теперь сопровождаются опровергающими доказательствами.

```
pip install -U chimera-agent
```
