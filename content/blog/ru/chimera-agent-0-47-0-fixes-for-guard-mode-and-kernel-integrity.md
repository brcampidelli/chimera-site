## Guard Mode теперь корректно сообщает об отказах

Ранее при отказе в вызове инструмента возвращалась строка наблюдения, не начинающаяся с `error:`, из-за чего система записывала операцию как успешную. Это затрагивало три компонента: desktop frame, логи шагов и обнаружение дрейфа. Запуск, где каждое опасное действие было заблокировано, выглядел успешным во всех структурированных данных, а модель даже сообщала о выполненных действиях вроде force push, которые никогда не происходили. Теперь ядро правильно помечает отказы, а текст отказа указывает, какой именно guard принял решение.

## Исправлено сопоставление правил для многострочных скриптов

Движок правил ранее интерполировал текст скрипта через `repr`, что экранировало переносы строк в два символа. Это нарушало границы слов в шаблонах правил, вызывая две проблемы:

1. Простые однострочные скрипты могли обходить защиту, так как `\n` сливался со следующим словом
2. Документы Markdown с цитатами опасных команд ошибочно блокировались

Два правила вообще никогда не срабатывали из-за этой ошибки. Теперь текст передается в правила без экранирования, соответствуя реальному поведению скриптов.

## Аудит-система больше не хранит секреты

Управляемая операция `write_file` сохраняла полное содержимое файла в `audit.jsonl`, включая конфиденциальные данные вроде `.env`-файлов или приватных ключей. Это происходило даже когда другой guard уже блокировал операцию. Теперь аудит редактирует чувствительный контент (используя существующий редактор, ранее применявшийся только для step traces) и записывает аргументы в форме документов только как метаданные с указанием размера.

## Видимость ядра добавлена в HTTP-эндпоинты

Решения ядра доверия не включались в HTTP-ответы для эндпоинтов run, batch и turn. Это означало, что клиенты не видели критически важные решения вроде одобрения force push. Теперь ядро корректно устанавливается на HTTP-поверхностях при `CHIMERA_GOVERNANCE` в `observe` или `enforce`. Важно: HTTP-развертывания никогда не запрашивают подтверждение на серверном терминале — лицо за этим термином не делало запрос.

## Другие исправления

- Цепочки аудита больше не ложно сообщают о подделке из-за конкурентных записей
- Режим `observe` теперь корректно подсчитывает отказы, которые должен был только измерять
- Зависшие воркеры больше не блокируют целые пакеты на неопределенное время
- Теперь можно настраивать лимиты ресурсов контейнеров
- Добавлен контроль бюджета контекста для терминального использования

## Известные ограничения

Команда явно документировала три текущих пробела вместо того, чтобы оставлять их для самостоятельного обнаружения:

1. Отчеты `observe` пока не отображаются в HTTP-интерфейсах
2. В API отсутствует путь одобрения в режиме `enforce`
3. Четыре HTTP-эндпоинта до сих пор не включают вердикты ядра

Обновите через `pip install --upgrade chimera-agent` или см. [Chimera Agent v0.47.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.47.0) для подробных примечаний к выпуску.
