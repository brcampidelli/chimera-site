## Безопасность прежде всего: привязка и аутентификация

В предыдущих версиях Chimera Agent по умолчанию предоставлялся неаутентифицированный шлюз на всех сетевых интерфейсах. `docker-compose.yml` публиковал порт 8765 глобально, а `.env.example` поставлялся без установленного токена. Это означало, что развертывание одной командой могло случайно создать открытый шлюз, доступный любому, кто обнаружит порт.

v0.45.0 меняет это тремя способами:
- Команда `serve` теперь отказывается привязываться к адресам вне loopback без токена аутентификации
- Docker Compose по умолчанию публикует только на `127.0.0.1`
- Добавлен флаг `--allow-insecure-bind` для легитимных случаев (например, аутентифицированных прокси)

Это критическое изменение для развертываний, где к шлюзу обращаются с другой машины. Установите `CHIMERA_SERVER_TOKEN` или используйте обходной путь при необходимости.

## Рабочий контроль расходов

До этого релиза единственными ограничениями были счетчики шагов — задача в цикле повторных попыток могла исчерпать весь баланс провайдера. v0.45.0 вводит три отдельных лимита:
1. Лимит на один запуск
2. Лимит на задачу (для запланированных операций)
3. Суточный агрегатный лимит, блокирующий запуск cron-задач

Вызовы без указанной цены теперь прерывают выполнение вместо молчаливого продолжения. Локальные модели считаются бесплатными, а не неизвестными, что предотвращает блокировку единственной конфигурации, которая не может превысить лимит. Запустите `chimera doctor`, чтобы проверить, можно ли установить цену для вашей модели по умолчанию перед настройкой лимитов.

## Унифицированное управление для всех компонентов

Раньше каждый компонент выполнения (`serve`, cron, MCP, A2A и адаптеры обмена сообщениями) создавал собственный реестр инструментов. Теперь единая функция `governed_profile()` формирует стек для всех пяти компонентов, а проверки AST на этапе сборки предотвращают регрессии.

Ключевая идея: режим `CHIMERA_GOVERNANCE=observe` позволяет измерить стоимость принудительного применения перед его включением. Он запускает полный стек, только записывая, что было бы заблокировано, предоставляя конкретные данные без риска для производства. По умолчанию остается `off` — управление должно быть явным.

Этот релиз также активирует долго бездействовавшую систему утверждения для вызовов опасного класса, устраняя избыточные блокировки (ложные срабатывания) без снижения эффективности защиты от атак.

## Что дальше

Обновитесь командой `pip install --upgrade chimera-agent` и проверьте настройки аутентификации и лимитов расходов в вашем развертывании. Для интеграции с редактором укажите в настройках агента `chimera acp --workspace <repo>`. Подробности в [релизных заметках][Chimera Agent v0.45.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.45.0).
