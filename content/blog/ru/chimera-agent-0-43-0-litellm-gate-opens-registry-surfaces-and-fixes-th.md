## Шлюз LiteLLM теперь принимает ключи любых провайдеров

Раньше Chimera распознавала только пять провайдеров LiteLLM, отвергая валидные ключи от таких сервисов, как Groq или Mistral, с misleading-ошибкой "No provider key configured". Теперь шлюз принимает любой `<PROVIDER>_API_KEY` с двумя защитными механизмами:

1. Чёрный список предотвращает ошибочную идентификацию сервисов вроде ElevenLabs или Stability AI как модельных провайдеров
2. `doctor` теперь проверяет названия провайдеров по enum LiteLLM, отлавливая опечатки, которые раньше приводили к тихим сбоям

Изменение решает более глубокую проблему: ключи в `.env` игнорировались из-за настройки Pydantic `extra="ignore"`. Поскольку `chimera init` создаёт `.env`-файлы, а документация указывает пользователям размещать ключи там, это вызывало постоянные сбои конфигурации.

## Ранее скрытые функции теперь доступны

Три важные возможности существовали в коде, но не имели интерфейса:

1. **Реестр агентов**: Поле ввода на доске было текстовым, угадывающим ID реестра, которые никогда не отображались. Теперь доступно через третью вкладку Automation, показывая существующих агентов, но позволяя создавать задачи и для несуществующих ID (они попадают в бэклог).
2. **Выбор модели эмбеддингов**: Ранее скрытая, эта опция теперь отображается прямо под переключателем семантической памяти, на который влияет. Сбои тихо деградируют к лексическому поиску, делая видимую конфигурацию критичной.
3. **Пул ключей**: Ротация round-robin с задержками не имела интерфейса. Теперь управление идёт по операциям (добавить/удалить) без отображения самих секретов.

## Критические исправления базовой функциональности

Две функции изначально работали некорректно:

- **Загрузка файлов и диктовка сообщений**: Обе операции падали с ошибками 422, потому что `authHeaders()` принудительно выставлял Content-Type `application/json`, ломая границы multipart-форм. Тесты пропускали это, так как мокали весь API-слой.

- **Сохранение сессий**: Приложение теряло тему, рабочее пространство и языковые настройки при запуске из-за случайного назначения портов, меняющего origin `localStorage`. Теперь порты сохраняются и повторно используются.

Мастер первого запуска теперь лучше обрабатывает выбор модели, показывая (но не применяя автоматически) совместимые модели для вашего провайдера, предотвращая мгновенные 401-ошибки.

Обновляйте через `pip install --upgrade chimera-agent` или смотрите полные детали в [Chimera Agent v0.43.0](https://github.com/brcampidelli/chimera-agent/releases/tag/v0.43.0).
